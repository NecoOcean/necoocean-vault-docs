## 一、设计目标与约束

### 1.1 目标用户与场景

目标用户是**工具的下载者与使用者**，不是浏览型访客。他们的典型路径是：从分享链接或搜索进入 → 判断这个工具是否解决自己的问题 → 找到下载按钮 → 下载 → （可选）留言反馈。

由此推出三条设计取向：

1. **信息密度优先于视觉留白**。首页即全量工具列表（PRD §三），用户要能在首屏扫到尽可能多的工具，而不是先看一段大标题动画。
2. **下载路径必须最短**。专题页的下载区是核心转化点，不应被视觉元素挤压。
3. **留言区要显得"有人管"**。这是本项目的差异化设计点——参考站是个人展示型模板，本项目是**反馈收集管道**，留言区的可信度（管理员回复的呈现、BUG 字段的结构化）直接影响用户是否愿意提交。

### 1.2 硬约束（来自既有决策，设计不得违反）

| 约束 | 来源 | 对设计的直接影响 |
|---|---|---|
| 首屏 gzip 后 ≤163 KB（JS ≤130 / CSS ≤15 / HTML ≤3 / API ≤15） | 架构说明 §7.4 | **不引 UI 组件库、不引动画库**（GSAP/Framer 一律不用，约 20–40 KB gzip）；开场动画用原生 CSS + JS 实现 |
| 一期不接入 CDN，3 Mbps 源站带宽 | 架构说明 §8 | 封面图走 COS 缩略图（≤120 KB/张）；**全站背景图须并入首屏预算核算**（见 6.4） |
| 严格前后端分离，后端不输出页面 | 架构说明 §2 | 所有视觉状态由前端渲染，无服务端注入的样式 |
| 一期不发送任何邮件 | ADR-002 | 留言区**不得出现"我们会邮件通知你"这类承诺文案** |
| 工具类型白名单 19 类、单文件 200 MB | 《待确认参数台账》A-18 | 下载区需容纳长文件名 + SHA-256 校验值，表格必须可横向滚动 |
| 留言先发后审 + 关键词标记 | PRD §9.3 | 留言提交后**不显示"待审核"字样**（先发后审，立即展示） |

## 二、视觉方向

### 2.1 参考站分析与取舍

参考站（`mobanwang.com/mb/lo202504`）的**开场动画机制**是本次要复刻的核心，源码实测结构如下：

```
<div class="amar_tm_loader-wrapper">   /* fixed 全屏，纯黑 #000，z-index 11111111 */
    <div class="loader"></div>          /* 高 1px、白色 #fff，绝对定位 */
</div>
```

其 `init.js` 中 `amar_tm_preloader()` 的实测时序：

| 步骤 | 实现 | 参数 |
|---|---|---|
| 定位 | 线条置于 `top: 高/2-2.5`、`left: 宽/2-200` | 视觉居中，预留 400px 总宽 |
| 生长 | `while` 循环逐次 `animate({width: zero}, 10ms)`，`zero += 3` 递增至 400 | 等效约 0.9s 匀速生长至 400px |
| 填充 | 先 `animate({left:0, width:'100%'})`，再 `animate({top:0, height:'100vh'})` | 线条→全屏色块，形成"吞噬"过渡 |
| 退场 | `setTimeout(..., 4500)` 后 `fadeOut('fast')` | 固定 4.5s 停留 |
| 移动端 | CSS `@media (max-width:1040px)` 中 `display:none` | 移动端直接跳过 |

**复刻的取舍**（三条刻意偏离，须向 NecoOcean 说明）：

1. **停留时长从固定 4.5s 缩短为约 2.8s，且与真实加载进度绑定**。原站是固定延时，用户等待时间与内容无关；本项目首屏有 163 KB 的预算约束，用真实进度驱动（`requestAnimationFrame` 计到 100%）能让动画在资源就绪时立即收尾，**避免"内容已好、动画还在演"的割裂感**。
2. **不做移动端直接隐藏，而是保留但压缩**。原站移动端 `display:none` 是因为桌面端动画依赖大量绝对定位计算；本设计改为纯 CSS transform 实现，移动端成本可忽略，保留动画有利于品牌感的一致性。
3. **必须响应 `prefers-reduced-motion`**。原站无此处理，这是无障碍缺陷，不予继承。

**未采纳的部分**：参考站的自动播放背景音乐（`init.js` 第 540 行 `append('<audio loop autoplay ...')`）**明确不移植**——自动播放音频是明确的可用性问题，且与工具站定位不符。参考站的"整屏固定 Hero + 背景图"结构也不照搬，原因见 2.2。

### 2.2 视觉基调

**深色为默认主题**，理由三条：

- 参考站开场动画的黑底白线，如果动画结束后跳进白色页面，会产生明显的亮度闪变；深色基调让开场与内容**无缝衔接**。
- 工具站的内容主体是图标、卡片、代码风格的标签（版本号、SHA-256、文件类型），深色能压住这些等宽字体的视觉噪点。
- 一期不公开上线、用户以开发者为主，深色更贴合使用习惯。

同时提供**浅色主题**（右上角切换按钮），通过 `data-theme` 属性整体换肤，所有颜色走 CSS 变量。**不做跟随系统的自动切换**——用户明确点击才算数，避免"白天打开是白的、晚上打开变黑的"不可预测感。

关于用户提供的截图（Docus 风格：白底、居中大标题、黑色主按钮、极简导航）：**其"克制的排版层级"被采纳**（大标题字号阶梯、克制的按钮数量、清晰的阅读列宽），但**其浅色基调不作为默认**，改为浅色主题的呈现方式。截图中的顶部搜索框被采纳并强化——因为工具站需要分类筛选与关键词搜索两个真实功能。

## 三、色彩系统

### 3.1 令牌表

颜色全部定义为 CSS 变量，定义在 `:root`（深色默认）与 `[data-theme="light"]` 两处。**改一处令牌即整体换肤，组件样式不含任何硬编码色值。**

#### 背景层（4 级）

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg-0` | `#08090C` | `#FFFFFF` | 页面底、开场遮罩 |
| `--bg-1` | `#0E1015` | `#F7F8FA` | 卡片、输入框默认底 |
| `--bg-2` | `#141720` | `#FFFFFF` | 卡片悬浮、导航悬浮项 |
| `--bg-3` | `#1B1F2A` | `#EEF1F6` | 图标底板、次级容器 |

> 深色四层是**递进变亮**（越靠前越亮），浅色四层是**递进变暗**。这一映射关系必须在实现时保持一致，否则悬浮态方向会反。

#### 文字层（3 级）

| 令牌 | 深色 | 浅色 | 对比度（深色底 `#08090C`） | 用途 |
|---|---|---|---|---|
| `--tx-1` | `#F2F4F8` | `#0D1220` | 17.8:1 | 标题、强调正文 |
| `--tx-2` | `#9BA3B4` | `#5A6478` | 8.2:1 | 正文、描述 |
| `--tx-3` | `#636B7D` | `#8A93A6` | 3.9:1 | 元信息、占位符 |

> **诚实标注**：`--tx-3` 对背景的对比度为 3.9:1，**低于 WCAG AA 正文要求的 4.5:1**。它有明确的使用边界——仅用于**非关键的元信息**（"更新于 3 天前"、输入框占位符、图标底板文字）。**禁止把 `--tx-3` 用于任何正文段落**。若审查要求全部达标，把 `--tx-3` 调至 `#7B8396`（4.9:1）即可，代价是元信息的视觉层级会弱化。

#### 品牌与语义色

| 令牌 | 值 | 用途 |
|---|---|---|
| `--brand` | `#3E7BFA`（浅色 `#2A5FD4`） | 主按钮、链接、聚焦环、当前分类 |
| `--brand-dim` | `#2A5FD4` | 主按钮悬浮 |
| `--brand-soft` | `rgba(62,123,250,.13)` | 卡片光晕、标签底 |
| `--ok` | `#2FA36B` | 在线状态、"NEW" 标记 |
| `--warn` | `#D99324` | 警示（留言关键词标记） |
| `--danger` | `#E05252` | 危险操作、表单错误 |

> 语义色**只承担状态含义，不承担装饰**。品牌色 `#3E7BFA` 与危险色 `#E05252` 在色相环上距离足够，且在深色底上亮度差异明显，色觉障碍用户可通过位置与文案区分。

### 3.2 边框

| 令牌 | 值 | 用途 |
|---|---|---|
| `--line-1` | `rgba(255,255,255,.07)`（浅色 `.08` 黑） | 默认分隔线、卡片描边 |
| `--line-2` | `rgba(255,255,255,.14)`（浅色 `.16` 黑） | 悬浮态、需要强调的边界 |

**深色界面的边框用半透明白而非实色**，这样边框在 `--bg-0` 到 `--bg-3` 的各层上都呈现一致的视觉重量。

## 四、排版系统

### 4.1 字体族

| 用途 | 字体栈 |
|---|---|
| 界面正文 | `"Inter", "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif` |
| 代码 / 数据 | `"JetBrains Mono", "SFMono-Regular", Consolas, monospace` |

**中英文混排说明**：`Inter` 不含中文字形，实际中文由 `HarmonyOS Sans SC` → `PingFang SC` → `Microsoft YaHei` 依次回退。这一顺序在 Windows（雅黑）与 macOS（苹方）上都能得到合理结果。

**性能提示（重要）**：`Inter` 与 `JetBrains Mono` 若以 webfont 形式引入，中文字体子集动辄数百 KB，**会直接击穿 163 KB 首屏预算**。因此：

- **正文中文字体一律走系统字体**，不下载 webfont；
- `Inter` / `JetBrains Mono` **仅使用拉丁子集**（`unicode-range` 限定），或干脆也回退到系统等宽字体；
- 等宽字体在本设计中承担"数据可信感"（版本号、SHA-256、文件大小），**系统等宽（Consolas / SF Mono）完全够用**，建议一期直接不引入 webfont。

### 4.2 字号阶梯

| 层级 | 字号 | 字重 | 行高 | 字距 | 用途 |
|---|---|---|---|---|---|
| Display | `clamp(38px, 6.2vw, 74px)` | 600 | 1.06 | `-0.035em` | Hero 主标题 |
| H2 | `clamp(26px, 3.4vw, 38px)` | 600 | 1.2 | `-0.028em` | 区块标题 |
| H3 | 16.5px | 600 | 1.4 | `-0.015em` | 卡片标题 |
| Lede | 17px | 400 | 1.7 | 0 | 导语段落 |
| Body | 16px | 400 | 1.6 | 0 | 正文基准 |
| Small | 14px | 400 | 1.65 | 0 | 卡片描述、导航项 |
| Caption | 13px | 400 | 1.6 | 0 | 辅助说明、按钮文字 |
| Mono-label | 11px | 400 | 1.5 | `0.2em` | 眉题、标签、等宽数据 |

**大标题使用负字距**（`-0.035em`）是刻意的：中文字形在放大后字间空隙会显得松散，收紧 3.5% 能让大标题更整、更接近参考站那种"块状标题"的视觉密度。

**仅使用两个字重**：400（常规）与 600（强调）。这是有意限制——多字重会导致视觉层级失控，且每个字重都会增加字体加载成本。

## 五、间距与栅格

### 5.1 间距阶梯（4px 基数）

| 令牌 | 值 | 典型用途 |
|---|---|---|
| `--sp-1` | 4px | 图标与文字间隙 |
| `--sp-2` | 8px | 标签之间、内联元素 |
| `--sp-3` | 12px | 按钮之间、表单行内 |
| `--sp-4` | 16px | 卡片内边距、网格间隙 |
| `--sp-5` | 24px | 卡片内边距（大）、区块内分组 |
| `--sp-6` | 32px | 区块标题与内容之间 |
| `--sp-7` | 48px | 区块内的大分组 |
| `--sp-8` | 64px | 区块之间的间隔（移动端） |
| `--sp-9` | 96px | 区块之间的间隔（桌面端） |

**基数取 4 而非 8 的原因**：本项目需要 4px 级别的精细控制（图标与文字的对齐、标签内边距），8 基数会产生大量 `calc()` 或半值。

### 5.2 容器与栅格

| 断点 | 容器最大宽 | 水平内边距 | 工具网格列数 |
|---|---|---|---|
| ≥1280px | 1240px | 24px | 自适应（约 4 列） |
| 1024–1279px | 1240px | 24px | 自适应（约 3 列） |
| 768–1023px | 100% | 16px | 自适应（2 列） |
| <768px | 100% | 16px | 1 列 |

网格用 `repeat(auto-fill, minmax(300px, 1fr))` 实现，**不写死列数**——工具数量是变化的（一期 6 个，未来可能 20 个），自适应网格能在任意数量下保持卡片宽度稳定。

### 5.3 圆角与描边

| 令牌 | 值 | 用途 |
|---|---|---|
| `--r-sm` | 8px | 标签、小按钮、图标按钮 |
| `--r-md` | 12px | 按钮、输入框、图标底板 |
| `--r-lg` | 16px | 卡片、面板 |
| `--r-xl` | 22px | 图像容器、肖像位 |

**描边宽度统一 1px**（深色下因半透明而显得更细）。不使用阴影做层级——深色界面的阴影几乎不可见，层级靠**背景亮度递进 + 描边**表达。仅两处例外：主按钮悬浮、规范面板悬浮，使用彩色投影制造"浮起"感。

## 六、组件规范

### 6.1 按钮

| 类型 | 底 | 文字 | 高度 | 圆角 | 悬浮 |
|---|---|---|---|---|---|
| Primary | `--brand` | `#FFFFFF` | 46px | `--r-md` | 底色转 `--brand-dim`，加彩色投影 |
| Ghost | `--bg-1` + `--line-2` 描边 | `--tx-1` | 46px | `--r-md` | 底色转 `--bg-2`，描边转 `--tx-3` |
| Icon | 透明 + `--line-1` 描边 | `--tx-2` | 34×34px | `--r-sm` | 描边转 `--line-2`，底色 `--bg-2` |
| Chip | `--bg-1` + `--line-1` 描边 | `--tx-2` | 自适应（padding 8/15） | 999px | 描边转 `--line-2` |
| Chip（选中） | `--tx-1` | `--bg-0` | 同 Chip | 999px | — |

**按钮所有状态必须有 `:active { transform: translateY(1px) }`**——这是"按下"的物理反馈，成本为零但显著提升操作确认感。

**触达尺寸**：图标按钮视觉尺寸 34×34px，**低于 WCAG 建议的 44px**。补偿方式是通过 `::-webkit-*` 与透明内边距把**实际可点击区域扩到 44×44px**，视觉上仍显示 34px。

### 6.2 工具卡片

这是首页的核心组件，结构五段：

```
┌─────────────────────────────────────┐
│ [图标 46px]  工具名  [NEW]           │  ← card-top
│              v2.4.1                 │
│                                     │
│ 简介文字，2–3 行，--tx-2 14px        │  ← card-desc
│                                     │
│ [Android] [离线] [SQLite]            │  ← card-tags
│ ─────────────────────────────────── │
│ 更新于 3 天前              详情 →    │  ← card-foot
└─────────────────────────────────────┘
```

> **图例**：`┌ ┐ └ ┘ ─ │` 卡片边界；`←` 指向右侧段落名注释。

**交互细节**：

- **悬浮抬升 4px**（`translateY(-4px)`），边框与底色同步变亮，300ms `cubic-bezier(.22,.61,.36,1)`；
- **指针跟随光晕**：卡片内有一个 `radial-gradient` 光斑，跟随鼠标位置移动（通过 `--mx` / `--my` 两个 CSS 变量实时写入）。这是本设计的**标志性微交互**，成本极低（三次属性写入），但让卡片有明确的"活的"质感；
- **"详情"箭头的间隙在悬浮时从 5px 增至 9px**，形成箭头"向前推"的暗示；
- 卡片整体是 `<a>` 标签，**键盘 Tab 可聚焦、Enter 可打开**；
- 进场时按索引错开 55ms 依次淡入上移。

### 6.3 搜索与筛选

- 搜索框高 44px，左侧 13px 处放放大镜，右侧放 `/` 快捷键提示（等宽小字）；
- **全局按 `/` 聚焦搜索框**（在 `<input>` 内按 `/` 不触发），这是工具站的效率习惯；
- 分类 chip 附带该分类下的工具数量（等宽小字），用户能预判点击后的结果；
- 搜索为**前端实时过滤**（一期工具数量少，无需请求后端），匹配名称 + 简介 + 标签三个字段；
- 空结果时显示引导文案，而非留白。

### 6.4 全站背景图（用户明确要求的可扩展空间）

> **口径修正（2026-09-21）**：本节原按"Hero 区背景图"表述，经 NecoOcean 澄清，所指为**整个页面的背景图**。已改为全站固定背景层实现，详见下方。原 Hero 局部槽位已合并进该层。

#### 结构：三层

```
z-index:-2  .page-bg        图片本体（position:fixed; inset:0; background-size:cover）
z-index:-1  .page-bg-veil   主题遮罩（浓度由主题令牌控制）+ 底部渐浓
  z-index:1+ 全部内容          导航 / Hero / 工具区 / 关于我 / 页脚
```

**为什么用 `position:fixed`**：图片层固定不随内容滚动，因此**整站只需一张图**——滚动时内容在图上"滑过"，视觉连续，且图片只解码一次。若改用 `background-attachment:fixed` 有移动端兼容问题；用 `absolute` 铺满文档高度则需要超长图片。

#### 遮罩浓度：经实测反推，不是拍脑袋定的

遮罩透明度直接决定正文对比度。按**最坏情形**测算（背景图该点恰为纯白 `#FFFFFF`）：

| 遮罩 | 实际底色 | `--tx-1` | `--tx-2` | 判定 |
|---|---|---|---|---|
| 86% | `#2B2B2E` | 12.82:1 | 5.57:1 | 通过 |
| **88%（默认）** | `#262729` | **13.58:1** | **5.90:1** | **通过，留有余量** |
| 90% | `#212224` | 14.46:1 | 6.29:1 | 通过 |
| 92% | `#1C1D1F` | 15.32:1 | 6.66:1 | 通过 |

**取值 88%**：在最坏情形下 `--tx-2` 仍有 5.90:1（AA 要求 4.5:1，余量 31%）。且**这已是纯白背景的极端假设**——真实照片几乎不会整片纯白，实际对比度只会更高。

> ⚠️ **改动前必读**：调低 `--page-veil` 会**直接削弱正文对比度**，且**图片内容不可控**（换图即换底）。任何下调都必须重跑上表测算，不能目测。

#### 两套主题的遮罩必须分开取值（易错点）

| 主题 | 遮罩令牌 | 值 | 理由 |
|---|---|---|---|
| 深色 | `--page-veil` | `rgba(8,9,12,.88)` | 深字变浅、底色深，方向一致 |
| 浅色 | `--page-veil` | `rgba(255,255,255,.88)` | **必须用白色系** |

**浅色主题若沿用深色遮罩，正文对比度会跌到 1 附近**（深色文字压在深色底上）——等于废掉整个内容区。这是本设计中最容易踩的坑，已在代码中用两套令牌隔开，并在 `[data-theme="light"]` 处写了警告注释。

#### 底部渐浓收口

遮罩带一层 `linear-gradient`：42% 以上维持基础浓度，78% 以下加深至 `--page-veil-2`（96%）。目的有二：

1. 长文（隐私政策）与留言区的可读性最稳；
2. 图片纹理在中下部自然淡出，页脚回归纯净。

#### 配置方式

```js
// prototype/index.html 顶部
var PAGE_BG = { src: '/assets/page-bg.webp' };
```

留空则自动加 `.is-empty`，三层结构退化为纯色底，**不发起任何图片请求**。

#### 图片规格与预算约束

| 项 | 要求 |
|---|---|
| 尺寸 | **1920×1080 以上**（需覆盖 4K 视口的 `cover` 裁切） |
| 格式 | **AVIF / WebP**，附 JPEG 兜底 |
| 体积 | **≤150 KB**，须与首屏 163 KB 预算合并计算 |
| 内容 | 避免在**文字密集区域**（左下 Hero、中部卡片区）出现高频细节 |
| 懒加载 | **不适用**——它是首屏元素，无法懒加载 |

> **必须说明的矛盾**：该图会**占用首屏预算**。当前首屏预算为 gzip 后 163 KB，一张 150 KB 的背景图会把总传输量推向约 300 KB，**直接违背 3 Mbps 下"并发 ≤3 人达标"的前提**。
> **三条可选路径**：① 压缩到 60~80 KB（牺牲细节，配合 88% 遮罩后视觉差异极小）；② 接受首屏劣化，把背景图列入演进阶段 1（产物迁 COS）之后再启用；③ 仅在桌面端加载。
> **这是需要 NecoOcean 决策的事项**，见 §十一 D-7。

#### 关于我页的肖像位（保留）

`.portrait` 槽位予以保留，与全站背景图是**两件独立的事**——它是页面内的内容图片，不是背景。

- 固定 4:5 竖版比例（移动端降为 1:1，最大宽 340px）；
- 规格标注：**880×1100、WebP/AVIF、≤120 KB**；
- 用 `aspect-ratio` 锁定比例，图片替换后**不会引起布局位移**（避免 CLS）；
- 它与背景图**互不冲突**：肖像位是内容层元素，铺在遮罩之上。

该槽位当前以虚线圈 + 等宽小字标注，**在原型中可见，接入真实图片后删除标注即可**。

### 6.5 表格（专题页下载区）

虽然原型未含专题页，但规范需要预留，因为它是最容易出问题的组件：

- 列：文件名 / 大小 / 上传时间 / 平台 / 版本号 / SHA-256；
- **SHA-256 完整值很长（64 字符）**，必须 `overflow-wrap:anywhere` 或提供"复制"按钮，否则会撑破表格；
- 窄屏下**表格容器横向滚动**（`overflow-x:auto`），而非压缩列宽；
- **不使用 `table-layout:fixed`**（本场景列宽差异大，fixed 会截断文件名），改用 `min-width` + 横向滚动。

## 七、动效规范

### 7.1 动效原则

1. **动效服务于状态变化，不做无意义的装饰**。全站只有三类动效：加载进度的表达（开场）、层级关系的表达（悬浮/按下）、空间关系的表达（滚动进场）。
2. **所有动效必须可被 `prefers-reduced-motion` 关闭**。开启后：开场动画直接跳过、滚动进场元素直接呈现最终态、状态胶囊的呼吸动画停止。
3. **缓动曲线统一两条**：
   - `--ease: cubic-bezier(.22,.61,.36,1)` —— 通用（悬浮、按压、颜色过渡）
   - `--ease-out: cubic-bezier(.16,1,.3,1)` —— 进场（元素从下方进来，起步快、收尾缓）

### 7.2 开场动画时序表

| 时间 | 阶段 | 元素 | 变化 | 时长 | 缓动 |
|---|---|---|---|---|---|
| 0ms | 遮罩就绪 | 全屏 `--bg-0` 遮罩 | 静态 | — | — |
| 80ms | 阶段① | 1px 白线 + 基准线 | 宽度 `0 → 400px`，`scaleX 0→1` | 900ms | `--ease` |
| 80ms | 阶段① | 百分数 `000` / 标识 `NECOOCEAN` | `opacity 0 → 1` | 400ms | `--ease` |
| 80–1180ms | 进度驱动 | 百分数文本 | `000 → 100`，`requestAnimationFrame` 逐帧 | 1100ms | 线性 |
| 1560ms | 阶段② | 填充块 | 从**中线的实际位置**向上铺满（`top → 0`, `height → 100vh`） | 620ms | `cubic-bezier(.76,0,.24,1)` |
| 1560ms | 阶段② | 百分数 / 标识 | `opacity 1 → 0` | 300ms | `--ease` |
| 2200ms | 阶段③ | 遮罩 + 填充块 | `opacity 1 → 0` | 500ms | `--ease` |
| 2680ms | 阶段④ | 页面主体 | 解锁滚动、导航加实底、滚动进场元素就绪 | — | — |

**关键实现细节**：阶段②的填充起点不是 `50vh` 硬编码，而是用 `getBoundingClientRect()` **读取线条的真实坐标**。这样当屏幕尺寸变化、或基准线位置调整时，填充始终从线条所在处开始，不会出现"从错误位置裂开"的视觉断层。这是参考站做不到的（它用 `WinHeight/2` 硬算）。

### 7.3 滚动进场

- 用 `IntersectionObserver`（**不引滚动监听库**）；
- 通用元素：`rootMargin: '0px 0px -26% 0px'`，即元素进入视口下部 26% 时才触发，避免"刚露头就动"的仓促感；
- 工具网格：`rootMargin: '0px 0px -12% 0px'`，触发时机略早，因为网格本身较大；
- 变化：`opacity 0→1` + `translateY(30px → 0)`，650–700ms；
- **触发一次即解绑**（`unobserve`），避免来回滚动反复播放。

### 7.4 微交互清单

| 交互 | 变化 | 时长 |
|---|---|---|
| 卡片悬浮 | `translateY(-4px)`、描边变亮、底色变亮、光晕显现 | 300ms |
| 卡片光晕跟随 | `--mx` / `--my` 实时写入 | 即时 |
| 卡片箭头间隙 | `5px → 9px` | 250ms |
| 按钮按下 | `translateY(1px)` | 180ms |
| 导航滚动变实 | 背景色 + 毛玻璃 + 下边框 | 350ms |
| 状态胶囊圆点 | 透明度呼吸 `1 → .35` | 2400ms 循环 |
| 卡片进场 | 按索引错开 55ms | 650ms |

## 八、响应式策略

**移动优先的降级原则**：不是简单地缩小元素，而是**删减信息**。

| 断点 | 变化 |
|---|---|
| ≤900px | 「关于我」由双栏变单栏；肖像位由 4:5 变 1:1，最大宽 340px |
| ≤768px | 导航链接隐藏、出现汉堡按钮；Hero 取消 `min-height:100vh`（避免小屏被强制拉长）；区块间距 96px → 64px；容器内边距 24px → 16px |
| ≤520px | 工具网格固定单列；Hero 数据字号 26px → 22px；区块标题下限 24px |

**Hero 高度处理说明**：桌面端 `min-height:100vh` 是为了让开场动画与首屏有完整的"落地"感；移动端取消该约束，改为内容自适应——因为手机竖屏的 100vh 会被浏览器地址栏动态变化影响，导致布局跳动（移动端 Safari 的经典问题）。

## 九、无障碍标准

| 项 | 标准 | 本设计的落实 |
|---|---|---|
| 正文对比度 | ≥4.5:1 | `--tx-1` 17.8:1、`--tx-2` 8.2:1 达标；**`--tx-3` 3.9:1 仅限元信息**（见 3.1 说明） |
| 大字号对比度 | ≥3:1 | 全部达标 |
| 键盘可达 | 全功能 | 卡片为 `<a>`、按钮为 `<button>`、搜索框可 Tab 聚焦、`/` 快捷聚焦 |
| 聚焦指示 | 可见 | 所有可聚焦元素有 `:focus-visible` 描边 |
| 触达尺寸 | ≥44px | 图标按钮通过透明内边距扩展；chip 高度 34px → 视觉可接受，实际热区扩至 44px |
| 动效敏感 | 尊重偏好 | `prefers-reduced-motion: reduce` 时跳过开场、关闭进场、停止呼吸动画 |
| 语义结构 | 正确的标题层级 | `h1`（Hero）→ `h2`（区块）→ 卡片标题为 `div`（因整体是链接，避免链接内嵌标题的语义冲突） |
| 图像替代 | 有 `alt` | 预留槽位接入图片时须填写有意义的 `alt` |
| 语言 | `lang="zh-CN"` | 已声明 |

**已知未达标项（诚实标注）**：

1. `--tx-3` 的 3.9:1 对比度不满足正文 AA 标准（使用边界已在 3.1 明确）；
2. 卡片标题使用 `div` 而非 `h3`，原因是卡片整体是链接，heading 标签嵌在链接内会破坏屏幕阅读器的标题导航。**取舍**：牺牲标题语义，换取链接语义正确。若审查要求，可改为"卡片内标题用 `h3` 包裹 `a`"，但需接受卡片内多处可点击热区。
3. **原型中未添加跳转到主内容的 skip link**，正式实现时应补 `<a href="#tools" class="skip-link">跳到工具列表</a>`。

## 十、工程落地约定

### 10.1 令牌落点

所有 CSS 变量应在前端工程中被抽取为**唯一来源**：

```
src/styles/
├── tokens.css      # :root 与 [data-theme=light] 的全部变量
├── base.css        # reset + 基础排版
└── components/     # 各组件样式，只引用变量，不写死色值
```

**验收方式**：`grep` 组件目录，应**搜不到任何 `#` 开头的十六进制色值**（除 `tokens.css`）。这是可机械验证的标准。

### 10.2 与首屏预算的对照

| 项 | 预算 | 本设计预估 | 说明 |
|---|---|---|---|
| HTML | ≤3 KB | ≈2.5 KB | 单页结构，无内联样式块 |
| CSS | ≤15 KB | ≈9.5 KB | 无 UI 框架，纯手写；gzip 后约 3 KB |
| JS（业务 + 框架） | ≤130 KB | 由 Vue 3 + 路由占用 | **本设计不增加 JS 依赖**：动画用 CSS + 原生 API，无动画库 |
| 字体 | 0 | **0** | 建议不引 webfont（见 4.1） |
| 图片 | 0 | **0（当前）** | 见下方说明 |

**结论（分两种情况）**：

1. **未配置全站背景图时**：本设计方案**不占用首屏预算**，全部视觉能力由 CSS 实现，JS 侧仅有约 60 行原生动画与过滤逻辑。
2. **配置全站背景图后**：该图**无法懒加载**（它是首屏元素），会直接进入首屏预算。**这是当前唯一会击穿预算的设计项**，必须做取舍——三条路径与量化影响见 §6.4。**该项待 NecoOcean 决策（D-7）。**

### 10.3 与参考站的差异汇总（供 NecoOcean 确认）

| 项 | 参考站 | 本设计 | 理由 |
|---|---|---|---|
| 动画时长 | 固定 4.5s | 约 2.8s，进度驱动 | 避免内容已就绪但动画仍在演 |
| 移动端 | `display:none` | 保留（压缩） | 纯 CSS 实现，成本可忽略 |
| 减少动效偏好 | 无处理 | 响应并跳过 | 无障碍要求 |
| 背景音乐 | 自动播放 | **不移植** | 明确的可用性问题 |
| Hero 结构 | 整屏固定 + 大背景图 | 内容自适应 + 全站背景层（固定 + 88% 遮罩） | 工具站以信息为主，故用强遮罩压住背景以保可读性 |
| 主色 | `#E9204F`（品红） | `#3E7BFA`（蓝） | 参考站主色偏时尚/个人；工具站取蓝，与"数据、可信、冷静"的调性一致 |

> **主色是可替换项**：若 NecoOcean 有品牌色偏好，只需改 `--brand` / `--brand-dim` / `--brand-soft` 三个令牌，全站随之变化。
