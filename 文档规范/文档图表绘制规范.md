# 文档图表绘制规范

**版本**：v1.0
**生效日期**：2026-09-21
**适用范围**：`necoocean-vault` 仓库内全部 Markdown 文档（`docs/doc/`、`docs/design/`）中的流程图、架构图、时序图、状态机、实体关系图、目录结构树等一切图形化表达。
**规范来源**：① 本规范语法层由现有 21 张图表归纳提炼；② 风格层继承 NecoOcean 既有的《开发技术文档插图 Prompt 统一手册》视觉基调（见 §六）。

> **本文档的定位**：在本规范落盘之前，仓库内图表**不存在可验收的绘制标准**——21 张图由多轮迭代各自形成，符号、箭头方向、列宽、图例口径互不一致。本规范的作用是**把隐含约定显式化**，使"合规"一词具备可判定性。

---

## 零、判定总则

### 0.1 四维核对面

每张图按以下四维核对，任一维不合格即判定为**不合规**：

| 维度 | 判定问题 |
|---|---|
| **A. 图形符号与连线** | 用的字符是否在白名单内？连线是否连续？箭头是否指向明确节点？有无悬空线段或悬空文字？ |
| **B. 命名与图例** | 同一实体在全文/全图是否同一名称？图例是否完备且与图中一致？编号体系是否统一？ |
| **C. 布局** | 左右边界是否对齐？列宽是否统一？缩进是否一致？有无断裂的竖直连接线？ |
| **D. 节点与层级关系** | 箭头方向是否表达真实依赖？层级是否体现真实调用/包含关系？有无语义错误的连线？ |

### 0.2 合规等级

| 等级 | 含义 | 处置 |
|---|---|---|
| **✅ 合规** | 四维全过 | 保留 |
| **⚠️ 轻微不符** | 影响观感但不影响语义（如个别行右边界差 1 字符） | 建议修正，可延后 |
| **❌ 不合规** | 违反语义正确性或可读性（如悬空箭头、连错节点、同名异实体） | 必须修改 |

### 0.3 判定纪律

- 判定必须能定位到**文件 + 章节 + 行号**，不接受"看起来还行"这类表述。
- 语义正确性优先于视觉美观：**一个对齐完美但连错方向的箭头，比一个对齐略歪但语义正确的箭头更不合格**。
- 同一信息在多份文档出现时，**以该信息的主文档为准**（如架构以《前后端分离架构说明》为准，数据模型以《系统设计文档》§5 为准），其余文档须与主文档口径一致。

## 一、字符集白名单（强制）

### 1.1 允许使用

**方框绘制（Box Drawing, U+2500–U+257F）**

```
─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼
```

**箭头**

```
→ ← ↑ ↓  ▲ ▼ ► ◄
```

**其他**

```
★ ⚠️ 🔒 · （用于标记，见 §1.3）
① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩ （用于步骤编号）
```

### 1.2 禁止使用

| 禁止项 | 原因 | 应替换为 |
|---|---|---|
| `╔ ╗ ╚ ╝ ═ ║`（双线框） | 与单线框风格冲突，且中文等宽字体下宽度不稳定 | 单线 `┌ ┐ └ ┘ ─ │` |
| `█ ▓ ▒ ░`（块元素） | 非矢量风格，与"扁平矢量"基调冲突 | 不使用 |
| `⇒ ⇐ ⇔`（双线箭头） | 与 `→ ←` 混用产生歧义 | `→ ←` |
| `⟶ ⟵`（长箭头） | 宽度不可控 | `──►` 用 `─` 拼接 |
| 全角空格、全角 `｜` | 列宽不可控，对齐必然失败 | 半角空格、半角 `│` |

> **半角/全角混排警告**：制图字符（`─│┌` 等）在**半角宽度**下渲染。若同一行混入中文（全角宽度），则该行总宽度 = 制图字符数 + 中文数 × 2。**框宽必须以"显示列宽"计算，不是字符数**。这是本仓库现有图表最普遍的失效原因。

### 1.3 标记符号语义（强制统一）

| 符号 | 含义 | 适用范围 |
|---|---|---|
| `⚠️` | 风险提示 / 易犯错处 | 图内注释行，或紧随图后的引用块 |
| `🔒` | 敏感字段 / 不对外暴露 | **仅用于数据模型图**（如 `contact_email 🔒`） |
| `★` | 关键约束 / 特殊说明 | 图内补充说明 |
| `①②③` | **有严格先后顺序**的步骤 | 时序图、状态机、流程步骤 |
| `·` | 并列要点（无先后） | 层级说明内的条目 |
| `（无符号）` | 普通注释 | 图内说明文字 |

**禁止**：把 `★` 与 `⚠️` 混用表达同一语义；把 `①` 用于无顺序的并列项。

### 1.4 变量占位符

- 使用 `<占位符>`：如 `https://<domain>/`、`{tool_id}/{version}/{uuid}.{ext}`、`<业务场景>`。
- **不得**用 `XXX`、`???`、`待填` 作为占位符。

## 二、节点与连线规范

### 2.1 节点框

**标准节点框**（框内文字与边界之间保留 1 空格）：

```
┌──────────┐
│ 节点名称  │
└──────────┘
```

**硬性要求**：

1. **上下边界长度必须相等**，且等于"框内最宽行的显示列宽 + 2"。
2. **左右竖线 `│` 必须对齐**：框内每一行的 `│` 位于同一显示列。
3. 框内文字**左对齐**（除节点名单独一行时可居中）。
4. **节点名称不超过 12 个汉字**；超长须换行或改用短名 + 图下注释。

**宽框（含多行内容）**：

```
┌──────────────────────────────┐
│           tools              │   ← 实体名居中
│ ──────────────────────────── │   ← 分隔线，长度 ≈ 框宽 - 4
│ id (PK)                      │
│ name / slug UNIQUE / summary │
└──────────────────────────────┘
```

### 2.2 箭头方向（强制统一）

| 场景 | 符号 | 示例 |
|---|---|---|
| 数据流 / 请求流向 | `──►` 或 `▼`（纵向） | `浏览器 ──► Nginx` |
| 依赖指向（A 依赖 B，箭头指向 B） | `──►` | `留言 ──► 工具` |
| 双向 | `◄──►`（**不得**用 `─►◄` 或 `◄───►` 混写） | `前端 ◄──► 后端` |
| 层级包含（上层 → 下层） | `│` + `▼` | 分层架构图 |

**三条硬性禁令**：

1. **禁止悬空箭头**——箭头必须一端连接到节点框边界，另一端指向另一节点框边界。
2. **禁止悬空文字**——图内任何文字必须位于节点框内，或通过 `│`/`├` 与某节点建立归属关系。（现有 `docs/doc/02-设计与实现/系统设计文档.md` §4.1 的 `留言/工具/分类` 一行即违反此条。）
3. **禁止方向混用**——同一张图内不得同时出现"箭头指向依赖方"和"箭头指向被依赖方"两种约定。

### 2.3 连线连续性

- 竖直连线跨行时，每行对应列必须有 `│`，**不得断开**。
- 分叉使用 `┬`，汇合使用 `┴`，交叉使用 `┼`。
- 拐角必须使用 `┌ ┐ └ ┘`，**不得**用 `├`/`┤` 代替拐角。

### 2.4 泳道图（时序图）专项

三列（或多列）泳道图的**列宽必须统一**，且每列的表头名称与竖直生命线对齐：

```
前端                    后端                      COS
 │                       │                        │
 │ ① 请求                │                        │
 ├──────────────────────►│                        │
 │                       │ 处理                    │
 │◄──────────────────────┤                        │
```

**硬性要求**：

1. 泳道数 **≤4**；超过 4 列改为拆图。
2. 每列起始列位**全图一致**（表头、生命线 `│`、箭头端点三者对齐）。
3. `① ② ③` 编号按**时间顺序递增**，不得跳号或重号。
4. 消息箭头长度按列距自动确定，**同一张图内所有同类箭头长度一致**。

> **建议**：时序图**优先考虑转 Mermaid `sequenceDiagram`**（见 §五），因为手绘 ASCII 泳道的列对齐维护成本极高，且每次编辑都易破坏对齐。

### 2.5 目录结构树专项

目录树**保留 ASCII 形式**（Mermaid 不擅长，且字符画在终端/diff 中更易读）。

```
project-root/
├── dir-a/
│   ├── file-1.js
│   └── file-2.js
└── dir-b/
    └── file-3.js
```

**硬性要求**：

1. **末项用 `└──`，非末项用 `├──`**，同一层级不允许出现两个 `└──`。
2. 缩进：子层级比父层级多 **4 个空格**（其中 2 个用于对齐父级竖线）。
3. 目录名**以 `/` 结尾**，文件名不带。
4. 行内注释统一使用 `# 注释`，注释起始列**同一层级内对齐**。
5. **目录树不得混入非文件系统内容**（如部署拓扑中的"CRON：mysqldump 每日备份"——见 §四.3）。

## 三、命名与图例规范

### 3.1 实体命名唯一性（强制）

同一实体在全仓库**必须只有一种写法**。当前需统一的关键实体：

| 实体 | 唯一写法 | 禁止的变体 |
|---|---|---|
| 前端应用 | `Vue 3 SPA` | `前端 dist`、`浏览器 SPA`、`Vue3 SPA` |
| 反向代理 | `Nginx` | `nginx`、`NGINX` |
| 后端应用 | `Spring Boot` | `SpringBoot`、`spring boot` |
| 数据库 | `MySQL 8` | `MySQL`、`mysql8` |
| 对象存储 | `腾讯云 COS`（首次出现可简称 `COS`，此后统一 `COS`） | `腾讯云对象存储`、`cos` |
| 部署单元 | `浏览器` / `Nginx` / `Spring Boot` / `腾讯云 COS` | 四单元顺序不得颠倒（体现请求流向） |

### 3.2 图例（Legend）

**触发条件**：图中出现以下任一情况时，**必须有图例**：

- 使用 ≥2 种箭头样式（实线/虚线、同步/异步）
- 使用 ≥2 种线型表达不同语义
- 使用符号标记（`🔒 ★ ⚠️`）

**图例位置**：图块正下方、紧跟图块，格式统一为：

```
图例：──► 同步调用  ┄┄► 异步消息  🔒 敏感字段  ★ 关键约束
```

**图例一致性**：图例中列出的每项**必须在图中实际出现**；图中出现的每种符号**必须图例中有定义**。两侧任一缺失即判定不合规。

### 3.3 编号体系

| 编号类型 | 用途 | 格式 | 示例 |
|---|---|---|---|
| `C-xx` | 接口编号 | 大写 C + 连字符 + 两位数字 | `C-28` |
| `A-xx` | 待确认参数台账 参数编号 | 大写 A + 连字符 + 两位数字 | `A-18` |
| `B-xx` | 验收用例集 用例编号 | 大写 B + 连字符 + 两位数字 | `B-29` |
| `D-x` | 待决策项 | 大写 D + 连字符 + 数字 | `D-7` |
| `Q-x` | 待确认问题 | 大写 Q + 连字符 + 数字 | `Q-5` |
| `①②③` | 图内步骤（**仅限图内**） | 圈号 | `① 校验` |
| `ADR-00x` | 设计决策记录 | 固定前缀 + 三位数字 | `ADR-001` |

**禁令**：图内步骤编号**不得**与外部的 `C-xx`/`A-xx` 编号体系混用（如不可写 `①C-28`）。

### 3.4 同图跨文档一致性（强制）

同一架构在多文档出现时，**必须描述一致**。当前存在的不一致：

| 架构 | 主文档（准） | 从文档（须对齐） |
|---|---|---|
| 整体架构 | `docs/doc/02-设计与实现/前后端分离架构说明.md` §三 | `docs/doc/02-设计与实现/系统设计文档.md` §2.1、§3.1 |
| 部署拓扑 | `docs/doc/02-设计与实现/前后端分离架构说明.md` §7.1 | `docs/doc/02-设计与实现/系统设计文档.md` §2.2、`docs/doc/02-设计与实现/技术选型与工程结构（方案对比）.md` §4.3 |
| 数据模型 | `docs/doc/02-设计与实现/系统设计文档.md` §5.1 | —— |
| 留言状态机 | `docs/doc/02-设计与实现/系统设计文档.md` §4.2 | `附录C`（文字描述） |
| 上传时序 | `docs/doc/02-设计与实现/系统设计文档.md` §4.3 | `docs/doc/02-设计与实现/前后端分离架构说明.md` §6.5（文字描述） |

**判定口径**：从文档与主文档**描述同一事实但画法不同**，若差异仅是风格（框宽、列数）→ ⚠️ 轻微不符；若差异涉及**内容**（节点有无、依赖方向、路径归属）→ ❌ 不合规。

## 四、布局规范

### 4.1 对齐判定方法（可脚本化）

对任意框型图，逐行计算**显示列宽**：

```
显示列宽 = 制图字符数 × 1 + 中文字符数 × 2 + 其他半角字符数 × 1
```

判定规则：

1. **同一框体的上/下边界**：显示列宽必须完全相等 → 否则 ❌。
2. **同一框体的左右竖线**：所在行的 `│` 显示列位必须等于边界首尾字符的列位 → 否则 ❌。
3. **多框并排**：各框的**首列列位**按固定步长排列（推荐步长 = 框宽 + 2 空格）。
4. **容差**：允许 ±1 显示列宽的偏差判为 ⚠️（部分编辑器的 CJK 字符渲染有 1 列浮动）；**>1 列判 ❌**。

> **实践建议**：由于中文宽度是双倍，**框内文字尽量用"中文 + 空格填充"凑齐显示列宽**，而非让框边界去适配文字。**框宽一旦确定，全图所有同层节点框共用该宽度。**

### 4.2 图块围栏（强制）

- 所有 ASCII 图**必须置于 fenced code block 内**。
- **语言标记统一为无标记**（即 ` ``` ` 后不写语言名），以区分于 ` ```nginx ` / ` ```json` / ` ```sql` 等真实代码块。
- **禁止**使用 ` ```text ` 或 ` ```ascii` 标记——本仓库既定风格为裸围栏，混用会破坏一致性。

> 例外：转 Mermaid 后**必须**标记为 ` ```mermaid `，与裸围栏 ASCII 图明确区分。这是两类图共存时的识别依据。

### 4.3 图表与正文的间距

```
（空行）
```（裸围栏开始）

...图内容...

```（裸围栏结束）
（空行）
```

- 图块前后**各留 1 个空行**。
- 图块**内部首尾不得有空行**。
- 图块**结束围栏后**若需说明，用引用块 `> ` 或直接正文，**不得把说明文字写进图内**（除归属于某节点的行内注释）。

### 4.4 图题与索引

**规模要求**：单个文档内图表 **≥3 张**时，须在图块**上方**加一行图题：

```
**图 4-1　模块总览与依赖关系**
```

格式：`**图 {章节号}-{序号}　{标题}**`（标题前用全角空格 `　`）。

**跨文档引用**：引用他文档的图时，格式为 `《系统设计文档》图 5-1`。

### 4.5 图块长度上限

- 单张图**不超过 40 行**；超过则拆分（如按子系统、按阶段拆）。
- 超长图的替代方案：① 转 Mermaid；② 改为分层多图；③ 改为表格。

## 五、Mermaid 转换规范

### 5.1 适用范围（本仓库既定决策）

| 图表类型 | 处理方式 | 理由 |
|---|---|---|
| 系统上下文图 | **转 Mermaid** `flowchart LR` | 结构清晰，Mermaid 原生支持 |
| 部署拓扑图 | **保持 ASCII**（目录树形式） | 本质是目录树，字符画更合适 |
| 分层架构图 | **转 Mermaid** `flowchart TB` + `subgraph` | `subgraph` 天然表达分层 |
| 模块依赖图 | **转 Mermaid** `flowchart TB` | 依赖方向表达更准确 |
| 状态机 / 流程图 | **转 Mermaid** `flowchart TD` | 分支逻辑原生支持 |
| 时序图（泳道） | **转 Mermaid** `sequenceDiagram` | 列对齐维护成本最高，收益最大 |
| 实体关系图 | **转 Mermaid** `erDiagram` | Mermaid 原生 ER 支持 |
| 目录结构树 | **保持 ASCII** | 非图论结构 |
| UI 布局骨架图 | **保持 ASCII** | 表达空间布局，非逻辑关系 |

**判定原则**：**图论结构（节点 + 边）转 Mermaid；空间/层级结构保留 ASCII。**

### 5.2 Mermaid 代码规范

1. 围栏标记：` ```mermaid `（**必须**，与裸围栏 ASCII 图区分）。
2. 节点 ID 使用**英文小写下划线**（`spring_boot`），显示文本用中文引号包裹：`spring_boot["Spring Boot"]`。
3. 同图内**方向统一**：`LR` 用于数据流，`TB` 用于分层。
4. 中文文本**避免**在 Mermaid 中使用标点（`／`、`（）`），改用半角或空格，防止渲染器解析异常。
5. 每条图**不超过 25 个节点**，超过则拆图。
6. 样式类（`classDef`）用于标记敏感/关键节点，**颜色须与 §六 视觉基调一致**。

### 5.3 转换时的内容守恒（强制）

转 Mermaid **不得丢失原 ASCII 图的信息**：

- 原图中的**全部注释文字**须以节点文本、边标签或图下说明保留。
- 原图中的**编号步骤**（`①②③`）须保留在边标签中。
- 原图中的**符号标记**（`🔒 ★ ⚠️`）须以 `classDef` 或边标签保留。
- 转图后须**在原位替换**，并在文档修订记录中登记。

### 5.4 双形态并存规则

若某图已在其他文档以 ASCII 形式存在，转 Mermaid 后**不强制**同步转换他文档，但**须在 §3.4 一致性表中登记主/从关系**，确保内容口径一致。

## 六、风格基调（继承既有 Prompt 库）

承自 NecoOcean《开发技术文档插图 Prompt 统一手册》的统一视觉基调，在 ASCII / Mermaid 形态下的等价表达：

| Prompt 库要求 | ASCII 等价 | Mermaid 等价 |
|---|---|---|
| 扁平矢量（flat vector） | 仅使用单线框（`┌─┐`），**不用双线框、不用块元素** | 默认 `flowchart`，不使用 `%%{init}%%` 引入 3D/阴影主题 |
| 无 3D / 无渐变 / 无阴影 | 不使用 `█ ▓ ▒ ░`、不使用字符阴影 | `classDef` 不使用 `shadow`、`gradient` |
| 蓝绿商务配色 | 无色（纯文本）；如需色彩语义，用 `★ 🔒 ⚠️` 标记区分 | `classDef` 使用蓝色系 `#3E7BFA`（项目主色）与其浅色变体，绿色系仅用于"通过/成功" |
| 无衬线字体工整 | 等宽字体 + 对齐（见 §4.1） | Mermaid 默认字体 |
| 节点对齐规整 | 见 §4.1 判定方法 | Mermaid 自动布局（无需人工对齐） |
| 高可读性 | 节点名 ≤12 汉字、单图 ≤40 行 | 单图 ≤25 节点 |
| 无装饰元素 | 禁止装饰性字符（`❀ ✿ ❖` 等） | 禁止装饰性 emoji（业务标记除外） |

> **注意**：Prompt 库面向 AI 绘图工具的**位图**输出；本规范面向 **Markdown 内嵌文本图**。二者共享视觉基调，但**规范对象不同**——本规范不涉及任何位图生成。
