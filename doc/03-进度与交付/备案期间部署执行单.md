## 一、本单与手册的差异（只有三条）

| # | 手册的做法 | 备案期间的替代 | 依据 |
|---|---|---|---|
| 1 | §2.6 Nginx 配「80 跳 443」+ 443 段 | **只配 80 段**，`server_name _;`，不写 443 | 证书未签，写 443 段会导致 `nginx -t` 因证书文件不存在而失败 |
| 2 | §2.7 签发 HTTPS 证书 | **整节跳过** | `certbot --nginx` 走 HTTP-01 验证，需域名已解析且 80 端口对外可达；大陆实例未备案前 80/443 的对外 Web 访问受拦截，验证必失败（且 Let's Encrypt 有失败频率限制） |
| 3 | 防火墙放通 22 / 80 / 443 | **只放通 22** | 备案期间网站不应对外开通；关闭 80/443 同时减少扫描面 |

**其余步骤与手册逐字一致。**

## 二、Phase 0：连上服务器（VS Code Remote-SSH）

### 0.1 控制台侧（一次性）

1. 确认实例「运行中」，记下公网 IP：`1.15.15.135`
2. 点「**重置密码**」设一个强口令 —— **重装系统后必须做一次**（重装会重置凭据）
3. 「管理防火墙规则」：确认放通 **22**；把 **80 / 443 先删掉或保持关闭**

**验证（本地 Windows PowerShell）**：
```powershell
Test-NetConnection 1.15.15.135 -Port 22
```
期望 `TcpTestSucceeded : True`。

### 0.2 本机安装扩展

VS Code → 扩展面板 → 搜索 `Remote - SSH`（发布者 **Microsoft**，ID `ms-vscode-remote.remote-ssh`）→ 安装。

### 0.3 写 SSH 配置

1. `F1` → 输入 `Remote-SSH: Open SSH Configuration File...` → 选 `C:\Users\NecoOcean\.ssh\config`
   （目录不存在时先在本地 PowerShell 执行 `New-Item -ItemType Directory -Force $env:USERPROFILE\.ssh`）
2. 写入：

```sshconfig
Host necoocean-tools
    HostName 1.15.15.135
    User ubuntu
    Port 22
    ServerAliveInterval 30
```

> Ubuntu 云镜像的默认登录用户是 **`ubuntu`**，不是 `root`；提权一律靠 `sudo`。

### 0.4 连接

1. `F1` → `Remote-SSH: Connect to Host...` → 选 `necoocean-tools`
2. 首次会提示主机指纹 → 选 `Continue`
3. 输入 `ubuntu` 的口令（= 0.1 里重置的那个）

**验证**：左下角状态栏显示 `SSH: necoocean-tools`；打开集成终端（`` Ctrl+` ``）执行：

```bash
whoami                                # 期望 ubuntu
head -n 2 /etc/os-release             # 期望 PRETTY_NAME="Ubuntu 22.04.x LTS"
```

### 0.5 连上后怎么用（三条要点）

1. **VS Code 以 `ubuntu` 身份运行，写不了 root 所有的文件**（`/etc/nginx/`、`/etc/systemd/system/`、`/etc/necoocean-tools.env`）。本单所有文件写入都写成 `sudo tee ... <<'EOF'` 形式，**直接在集成终端里整段粘贴**，不要在编辑器里改。
2. 编辑器用来**浏览与检索**没问题（这些文件是 644，可读）。
3. **端口转发是本单的关键工具** —— 见 Phase 6，它让你在备案前就能在本地浏览器跑完整链路。

### 0.6（可选，推荐）改用密钥登录

本地 PowerShell：

```powershell
ssh-keygen -t ed25519 -C "necoocean-vault"      # 已有密钥则跳过
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

服务器集成终端（把上一步输出的**整行**粘进去）：

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '<粘贴公钥整行>' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

再在 `~/.ssh/config` 的 `Host necoocean-tools` 下加一行 `IdentityFile C:\Users\NecoOcean\.ssh\id_ed25519`，重连即免密。

## 五、Phase 3：数据库初始化

```bash
sudo mysql
```

进入 MySQL 后执行（`<数据库口令>` 自建，≥16 位，**记下来 Phase 4 要用**）：

```sql
CREATE DATABASE necoocean_tools CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'necoocean'@'127.0.0.1' IDENTIFIED BY '<数据库口令>';
GRANT ALL PRIVILEGES ON necoocean_tools.* TO 'necoocean'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

**表不要手建**，启动应用时由 Flyway 写入。

确认 MySQL 不对外监听，并按既定决策设置缓冲池。

`bind-address` 在 Ubuntu 的 MySQL 8 上默认就是 `127.0.0.1`（本机实测已确认），**不用改**。只需补一个独立配置文件（**不修改发行版自带的 `mysqld.cnf`**，避免升级时被覆盖或被 sed 反复追加）：

```bash
sudo tee /etc/mysql/mysql.conf.d/zz-necoocean.cnf >/dev/null <<'EOF'
[mysqld]
innodb_buffer_pool_size = 1G
EOF
sudo systemctl restart mysql
```

> `zz-` 前缀保证它排在 `mysqld.cnf` **之后**被加载（`/etc/mysql/my.cnf` 用 `!includedir /etc/mysql/mysql.conf.d/` 按文件名字典序引入），因此同名的后出现的值生效。
> 取值来自《技术选型与工程结构（方案对比）》：4 GB 机器按「JVM 堆 1G + 缓冲池 1G，余 2G 留给系统与 Nginx」分配。**本项目数据量极小，跳过它不会有可观测差异**；写上是为了让运行参数与文档决策一致。

**验证**：

```bash
ss -ltnp | grep -E '3306|33060'                                                 # 期望只有 127.0.0.1
sudo mysql -e "SELECT @@innodb_buffer_pool_size/1024/1024 AS buffer_pool_MB;"   # 期望 1024
```


```bash
sudo tee /etc/necoocean-tools.env >/dev/null <<'EOF'
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://127.0.0.1:3306/necoocean_tools?characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
DB_USERNAME=necoocean

ADMIN_USERNAME=admin
ADMIN_PASSWORD=<管理员口令>
COS_PROVIDER=tencent
COS_REGION=ap-shanghai
COS_BUCKET=necoocean-vault-1381413798
COS_SECRET_ID=<CAM 子用户 SecretId>
COS_SECRET_KEY=<CAM 子用户 SecretKey>
EOF
sudo chmod 600 /etc/necoocean-tools.env
```

**三处占位符的取值**：

| 占位符 | 取值 |
|---|---|
| `<数据库口令>` | Phase 3 建号时用的那个，保持一致 |
| `<随机长字符串>` | IP 哈希盐。用 `openssl rand -base64 36` 生成；**不要用开发默认值 `dev-only-ip-salt`** |
| `<管理员口令>` | 8～72 位。**仅在 `admin_users` 表为空时创建账号**，库里已有管理员则此项不生效 |

> ⚠️ **两类变量缺项的后果相反**：`IP_HASH_SALT` 缺失 → **`prod` 下直接启动失败**；`COS_*` 四项任一缺失 → **不报错，但对象存储静默降级为 `Unavailable`**，上传与下载签名全部失效。

**验证文件内容**（注意不能回显 `COS_SECRET_KEY` 的完整值给不该看到的人）：

```bash

sudo ls -l /etc/necoocean-tools.env           # 期望 -rw------- root root
```

### 6.3 注册 systemd 服务并启动

```bash

[Unit]
Description=NecoOcean tools API
After=network.target mysql.service

[Service]

EOF

sudo systemctl enable --now necoocean-tools
```

**验证**：`test -f /var/www/necoocean-tools/index.html && echo OK`

### 7.2 Nginx 配置（**备案期间版：只有 80 段**）

```bash
sudo tee /etc/nginx/sites-available/necoocean-tools >/dev/null <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name _;

    root /var/www/necoocean-tools;
    index index.html;

    gzip on;
    gzip_types text/html text/css application/javascript application/json;
    gzip_min_length 1024;
    gzip_comp_level 6;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /download/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sfn /etc/nginx/sites-available/necoocean-tools /etc/nginx/sites-enabled/necoocean-tools
sudo nginx -t && sudo systemctl reload nginx
```

> **与手册 §2.6 的差异**：删掉了「80 跳 443」与整个 443 段（证书未签）；`server_name` 用 `_` 占位。`listen [::]:80;` 是本机 IPv6 已开启所需（手册 §2.6 已注明）。

**验证**：

```bash
sudo nginx -t                                         # 期望 syntax is ok
curl -sI http://127.0.0.1/ | head -n 1                # 期望 HTTP/1.1 200 OK
curl -s http://127.0.0.1/api/v1/public/health         # 期望 JSON，code 为 0
curl -s http://127.0.0.1/api/v1/public/tools | head -c 200   # 期望 JSON 信封
```

## 八、Phase 6：用 VS Code 端口转发，在本地浏览器跑真实链路

这一步是备案前最有价值的部分——它让你**不依赖域名与备案**，把一期能力全部真机验证一遍。

### 8.1 转发 Nginx 的 80 端口

1. VS Code 底部面板切到「**端口 / PORTS**」标签（或 `Ctrl+Shift+P` → `Ports: Focus on Ports View`）
2. 点「**转发端口 / Forward a Port**」→ 输入 `80`
3. VS Code 会给出本地地址，形如 `http://localhost:8000`（本地 80 被占用时会自动换端口）

### 8.2 在本地浏览器打开

访问 VS Code 给出的 `http://localhost:<本地端口>`。

> ⚠️ **必须用 `localhost`，不要用公网 IP**。本项目两个 Cookie（`SESSION` 与 `csrf_token`）都带 `Secure` 属性；Chrome / Edge / Firefox 把 `localhost` 视为可信来源、允许存取 `Secure` Cookie，而 `http://<公网IP>` 不行，会导致登录后会话不保持。
> 若浏览器实测仍拒绝 Cookie，退路有两条：① 用 `curl -c cookies.txt -b cookies.txt` 验证接口链路；② 在 Nginx 上临时加自签证书走 https。

### 8.3 逐项打勾（真实链路抽测）

| # | 操作 | 期望 / 验证方式 |
|---|---|---|
| 1 | 首页 | 工具卡片正常渲染；控制台无 404 |
| 2 | 后台登录 | 用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录成功，进入仪表盘 |
| 3 | **上传文件（最关键）** | 后台建工具 → 上传一个文件 → 成功。**这一步同时验证了 COS 桶 CORS、CAM 密钥、桶名与地域四项**；失败时先查 CORS 是否含 `PUT` 与 `Content-Type` 头 |
| 4 | 前台下载 302 | 专题页点下载，浏览器拿到对象；服务端 `curl -sI http://127.0.0.1/download/<file_id> \| head -n 1` 期望 `302` |
| 5 | 留言提交 | 专题页提交一条留言 → 前台即时可见 |
| 6 | 管理员回复 | 后台回复 → 前台可见 |
| 7 | 导出 + 审计 | 后台导出一次（**默认不勾邮箱**）→ 下载到文件 |

**数据库侧对账**（三条"一行验真"）：

```bash
sudo mysql -e "SELECT
 (SELECT COUNT(*) FROM necoocean_tools.messages)        AS messages,
 (SELECT COUNT(*) FROM necoocean_tools.message_replies) AS replies,
 (SELECT COUNT(*) FROM necoocean_tools.resource_files)  AS files,
 (SELECT download_count FROM necoocean_tools.resource_files ORDER BY id DESC LIMIT 1) AS dl,
 (SELECT COUNT(*) FROM necoocean_tools.export_audit_logs) AS exports,
 (SELECT include_email FROM necoocean_tools.export_audit_logs ORDER BY id DESC LIMIT 1) AS inc_mail;"
```

判读口径：

- `messages` / `replies` 相比上一步**各 +1** ⇔ 公开提交与后台回复真跑过
- `dl > 0` ⇔ 真实对象存在且 302 已发出
- `exports > 0` 且 `inc_mail = 0` ⇔ 导出接口被调用过，且「默认不含邮箱」生效（`ExportService.export()` 在返回文件前同步写审计，**0 行等价于从未被调用**）

## 十、备案通过后要补的三件事

1. **改 Nginx**：`server_name _;` → 真实域名；加回「80 跳 443」与 443 段（照抄手册 §2.6 原文）
   ⚠️ 443 段里**必须写 `listen 443 ssl http2;`**，**不能写 `http2 on;`**——本机装的 nginx 是 **1.18.0**（2026-09-23 实测），而 `http2 on;` 自 nginx **1.25.1** 才引入，写了会让 `nginx -t` 报 `unknown directive "http2"`。改完**先跑 `sudo nginx -t` 再 reload**。
2. **放通防火墙 80 / 443**，并 `sudo nginx -t && sudo systemctl reload nginx`
3. **签证书**：`sudo apt-get install -y certbot python3-certbot-nginx && sudo certbot --nginx -d <域名>`，随后 `sudo certbot renew --dry-run` 验证

做完后，把本单移入 `docs/doc/_archive/`，部署知识回归 `部署运维手册`。
