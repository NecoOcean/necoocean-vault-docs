## 四、下一步待办（按优先级）

### P0 — 阻塞项，建议立即处理

#### 1. 文档仓库建立 git 版本控制

**现状**：`necoocean-vault/` 根目录**没有 `.git`**（实测 `Test-Path .git` = False）。后端目录有独立仓库，但 **12 份文档、7 份规范、UI 规范与原型全部处于无版本控制状态**。

**风险**：
- 无法回溯任何文档改动，与「变更可追溯」支柱直接冲突
- 无远程备份，一次误操作即永久丢失
- 后端 `.gitignore` 已覆盖 `target/`、`logs/`，但文档仓库**无任何保护**

**建议动作**：
1. `git init` 根目录，写 `.gitignore`（排除 `.workbuddy/`、`.tmp-research/`）
2. 首次提交全部文档，`git add` 后**先确认文件清单再提交**（本机曾有 `git rm` 意外删除 17 个未跟踪文件的记录，见长期记忆）
3. 建 GitHub 私有仓库并关联 remote
4. 决定后端目录的处理：**留作嵌套仓库**（加 `.gitignore` 排除）**或**改为根仓库的一个子目录单仓库管理

> ⚠️ 这是本次分析中**唯一发现的实质性风险项**，且与开发进度无关、纯属基础设施缺口。

#### 2. 决策 UI 层 D-7（全站背景图 vs 首屏预算）

**冲突本质**：背景图是首屏元素、无法懒加载，一张 150 KB 的图会把首屏总传输量推到约 300 KB，**直接违背 3 Mbps 下「并发 ≤3 人达标」的前提**。

**三条路径**（规范已列）：
- ① 压到 60~80 KB 再启用（配 88% 遮罩后视觉差异极小）
- ② 延到演进阶段 1（前端产物迁 COS）之后再启用
- ③ 仅桌面端加载

**当前默认不配置**（`PAGE_BG.src = ''`），原型维持纯色底。**不决策不阻塞后端开发，但阻塞前端首页定稿。**

## 五、需要注意的风险与遗留

### 5.1 实质风险

| # | 风险 | 证据 | 影响 |
|---|---|---|---|
| 1 | **文档仓库无版本控制** | 根目录无 `.git`（实测） | **高**——12 份文档 + 7 份规范无回溯、无备份 |
| 2 | 文件两阶段直传（第 8 步） | 《系统设计文档》标注"风险最高" | 高——需真实 COS 环境验证，孤儿对象清理须可靠 |
| 3 | 3 Mbps 带宽 + 全站背景图 | UI 规范 D-7 | 中——影响前端首页定稿 |
| 4 | 后端骨架工作**未记入记忆** | memory 中 `necoocean-tools-backend` 零命中 | 低——跨会话易丢失上下文 |

### 5.2 需保持的口径纪律（易写错）

- 实体关系 **8 实体 / 5 条外键**（正文曾误记 4 条）
- 会话/登录态是**跨前后端两层的共享存储**，不属任何一层独占
- 浅色主题遮罩必须用 `rgba(255,255,255,.88)`，套深色遮罩会让正文对比度跌到 1 附近
- 参数变更须同步检查《待确认参数台账》§四「上游影响索引」列出的全部章节

### 5.3 本机环境（影响执行方式）

- Bash 工具不可用 → 一律用 PowerShell + Read/Write/Edit/Glob/Grep
- PowerShell stdout 常不回传 → 脚本内 `Out-File` 写文件后再 Read
- PowerShell 重定向 `>` 写出 UTF-16LE，Read 会拒读，需先转 UTF-8
- `Add-Type` 被安全策略拦截 → 需 .NET 能力时改用 Python
- 同一文件的多次编辑**不可并行**（后写覆盖前写，且两者都报成功）
