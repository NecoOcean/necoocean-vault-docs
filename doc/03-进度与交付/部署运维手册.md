# 部署运维手册

- **文档版本**：v1.0
- **日期**：2026-09-22
- **读者**：在一台 Linux 服务器上把本站跑起来的人
- **当前状态**：一期不公开上线。对象存储已接入：上传走预签名直传，下载成功时 302 至预签名 URL

架构拓扑以《前后端分离架构说明》§七为准。本文只写可执行步骤。尖括号是要替换的值，取值来源写在该步里。

---

## 一、环境要求

| 项 | 要求 |
|---|---|
| 服务器 | 腾讯云轻量应用服务器，上海五区，4C4G，系统盘 40 GB，带宽 3 Mbps |
| 操作系统 | Ubuntu 22.04 或 24.04 |
| JDK | 17。构建机和服务器都要 |
| MySQL | 8.0 及以上。本机已用 8.4.4 跑通 V1～V4 |
| Nginx | 发行版自带的稳定版 |
| Node | 只装在构建前端的电脑上。服务器不装 |
| 对象存储 | 腾讯云 COS，桶必须建在上海。须配置 CORS，密钥用环境变量注入 |

应用只监听 `127.0.0.1:8080`。MySQL 只监听 `127.0.0.1:3306`。公网只开 22、80、443。

## 二、首次部署

### 2.1 服务器初始化

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo mkdir -p /opt/necoocean-tools /var/www/necoocean-tools /var/backups/necoocean-tools
sudo useradd --system --home /opt/necoocean-tools --shell /usr/sbin/nologin necoocean
sudo chown necoocean:necoocean /opt/necoocean-tools
```

**验证**：`timedatectl` 显示 `Asia/Shanghai`；`id necoocean` 能打出系统用户。

### 2.2 依赖安装

```bash
sudo apt-get update
sudo apt-get install -y openjdk-17-jre-headless nginx mysql-server
java -version
mysql --version
nginx -v
```

**验证**：`java -version` 是 17；`systemctl is-active mysql nginx` 都是 `active`。

### 2.3 数据库初始化

口令只写在服务器上，不写进仓库。

```bash
sudo mysql
```

```sql
CREATE DATABASE necoocean_tools CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'necoocean'@'127.0.0.1' IDENTIFIED BY '<数据库口令>';
GRANT ALL PRIVILEGES ON necoocean_tools.* TO 'necoocean'@'127.0.0.1';
FLUSH PRIVILEGES;
```

`<数据库口令>` 自己生成，至少 16 位，记到第 2.4 步的环境文件里。仓库里的 `create_database.sql` 只建库，不建账号；上面这段已经包含建库，不必再跑那份脚本。

确认 MySQL 不对外网监听。`/etc/mysql/mysql.conf.d/mysqld.cnf` 中：

```ini
bind-address = 127.0.0.1
```

```bash
sudo systemctl restart mysql
```

**验证**：`ss -ltnp | grep 3306` 只出现 `127.0.0.1:3306`。表先不要手建，下一步启动应用时由 Flyway 写入。

### 2.4 应用部署

在构建机上，进入后端仓库：

```bash
mvn -B -DskipTests package
```

合并前仍要先跑一次 `mvn -B verify`。上传的是 `target/necoocean-tools-backend-0.1.0-SNAPSHOT.jar`。

```bash
scp target/necoocean-tools-backend-0.1.0-SNAPSHOT.jar <服务器用户>@<服务器地址>:/tmp/necoocean-tools-backend.jar
```

在服务器上：

```bash
sudo install -o necoocean -g necoocean -m 640 /tmp/necoocean-tools-backend.jar /opt/necoocean-tools/necoocean-tools-backend.jar
sudo tee /etc/necoocean-tools.env >/dev/null <<'EOF'
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://127.0.0.1:3306/necoocean_tools?characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
DB_USERNAME=necoocean
DB_PASSWORD=<数据库口令>
IP_HASH_SALT=<随机长字符串>
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<管理员口令>
EOF
sudo chmod 600 /etc/necoocean-tools.env
```

`<管理员口令>` 长度 8～72。库里已经有管理员之后，再改这个值不会覆盖原口令。`<随机长字符串>` 用来和客户端 IP 拼接后做 SHA-256，生产环境不要用开发默认值 `dev-only-ip-salt`。

```bash
sudo tee /etc/systemd/system/necoocean-tools.service >/dev/null <<'EOF'
[Unit]
Description=NecoOcean tools API
After=network.target mysql.service

[Service]
User=necoocean
Group=necoocean
WorkingDirectory=/opt/necoocean-tools
EnvironmentFile=/etc/necoocean-tools.env
ExecStart=/usr/bin/java -jar /opt/necoocean-tools/necoocean-tools-backend.jar
Restart=on-failure
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now necoocean-tools
```

**验证**：`systemctl status necoocean-tools` 为 `active (running)`。日志里出现 Flyway `Successfully validated` 或 `Successfully applied`，并且没有 Hibernate 校验失败。然后：

```bash
curl -s http://127.0.0.1:8080/api/v1/public/health
```

返回 JSON，且 `code` 为 0。

```bash
mysql -unecocean -p -h 127.0.0.1 necoocean_tools -e "SELECT version, success FROM flyway_schema_history ORDER BY installed_rank;"
```

每一行 `success` 都是 1，版本至少到 3。

### 2.5 前端部署

前端仓库还没有建立。建立之后在本地构建，不要在服务器上装 Node：

```bash
npm run build
scp -r dist/* <服务器用户>@<服务器地址>:/tmp/necoocean-frontend/
```

```bash
sudo rsync -a --delete /tmp/necoocean-frontend/ /var/www/necoocean-tools/
```

**验证**：`test -f /var/www/necoocean-tools/index.html` 成功。在前端仓库出现之前，跳过这一步，Nginx 的页面根目录可以先空着。

### 2.6 Nginx 配置

```bash
sudo tee /etc/nginx/sites-available/necoocean-tools >/dev/null <<'EOF'
server {
    listen 80;
    server_name <域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name <域名>;
    ssl_certificate /etc/letsencrypt/live/<域名>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<域名>/privkey.pem;

    root /var/www/necoocean-tools;
    index index.html;

    gzip on;
    gzip_types text/html text/css application/javascript application/json;
    gzip_min_length 1024;
    gzip_comp_level 6;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /download/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
sudo ln -sfn /etc/nginx/sites-available/necoocean-tools /etc/nginx/sites-enabled/necoocean-tools
sudo nginx -t && sudo systemctl reload nginx
```

> 必须把 `X-Forwarded-For` 传给应用，应用只取第一段。缺了这个头，或者第一段是内网地址时，留言限流会跳过该请求，不会把所有访客算进同一个桶。

证书还没签发时，先不要启用上面的 443 段。本机调试继续用 `http://127.0.0.1:8080`。

**验证**：`sudo nginx -t` 显示 `syntax is ok`。

### 2.7 HTTPS 证书

一期不公开时可以不做。要公开时：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d <域名>
```

**验证**：`sudo certbot renew --dry-run` 成功。

### 2.8 部署后验证

- [ ] `curl -s http://127.0.0.1:8080/api/v1/public/health` 返回 `code` 为 0 的 JSON
- [ ] `curl -s http://127.0.0.1:8080/api/v1/public/tools` 返回 JSON 信封
- [ ] jar 内没有页面：`jar tf /opt/necoocean-tools/necoocean-tools-backend.jar | grep -c '\.html$'` 结果为 0
- [ ] 除下载接口外，响应的 `Content-Type` 含 `application/json`
- [ ] `flyway_schema_history` 中已执行版本的 `success` 全是 1
- [ ] `ss -ltnp | grep -E '8080|3306'` 只绑定 `127.0.0.1`
- [ ] 经 Nginx 访问时，应用日志里的客户端 IP 不是 `127.0.0.1`
- [ ] `flyway_schema_history` 最新成功版本为 `4`（含 `object_status`）
- [ ] 已配置 COS 密钥与桶 CORS；已上架且对象存在的文件，`GET /download/{file_id}` 返回 **302**，且响应与日志中不出现对象键原文
- [ ] 库有记录但 COS 无对象时返回 `40405`，后台 `object_status` 变为异常

## 三、配置项

### 3.1 环境变量

| 变量 | 作用 | 缺了会怎样 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 生产设为 `prod` | 会带上开发默认值 |
| `DB_URL` | JDBC 地址 | `prod` 下启动失败 |
| `DB_USERNAME` | 数据库账号 | `prod` 下启动失败 |
| `DB_PASSWORD` | 数据库口令 | `prod` 下启动失败 |
| `IP_HASH_SALT` | IP 哈希盐 | `prod` 下启动失败 |
| `ADMIN_USERNAME` | 首次创建的管理员名，默认 `admin` | 使用默认名 |
| `ADMIN_PASSWORD` | 仅在管理员表为空时创建账号 | 打一行日志后继续启动，不创建账号 |
| `COS_PROVIDER` | `tencent`（默认）或 `memory`（仅测试） | 默认腾讯云 |
| `COS_REGION` | 桶地域，须 `ap-shanghai` | 无法签发预签名 |
| `COS_BUCKET` | 桶名 | 无法签发预签名 |
| `COS_SECRET_ID` | 子用户 SecretId | 无法签发预签名 |
| `COS_SECRET_KEY` | 子用户 SecretKey | 无法签发预签名 |

### 3.2 数据库连接

生产账号只用 `necoocean`@`127.0.0.1`，不要用 `root`。字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`。Flyway 需执行到 **V5**（含 `export_audit_logs`）。

### 3.3 对象存储

桶建在上海，和服务器同地域。私有读写；上传预签名 60 分钟，下载预签名 5 分钟。密钥只放环境变量或已忽略的 `config/local.yml`，**不要进仓库**。浏览器直传前须在桶上配置 CORS（允许前端 Origin 的 `PUT`/`GET`/`HEAD`）。封面上传接口一期未单独实现，`cover_url` 仍可为 `null`。

## 四、日常运维

### 4.1 启停与重启

```bash
sudo systemctl restart necoocean-tools
sudo systemctl stop necoocean-tools
sudo systemctl start necoocean-tools
```

**验证**：`systemctl is-active necoocean-tools` 与你执行的动作一致，健康检查仍返回 JSON。

### 4.2 日志查看

```bash
sudo journalctl -u necoocean-tools -n 200 --no-pager
```

应用自己的文件日志在工作目录的 `logs/`，按天滚动，保留 15 天。日志里不记查询串、请求体和口令。

### 4.3 数据库备份与恢复

```bash
mysqldump -unecocean -p -h 127.0.0.1 --single-transaction necoocean_tools \
  > /var/backups/necoocean-tools/necoocean_tools_$(date +%Y%m%d).sql
```

建议每天 cron 跑一次。恢复：

```bash
mysql -unecocean -p -h 127.0.0.1 necoocean_tools < /var/backups/necoocean-tools/<备份文件>
```

> 恢复会用备份覆盖当前库里的数据。执行前先再备一份当前库。

**验证**：恢复后 `SELECT COUNT(*) FROM tool_categories;` 能查出行，应用能启动并通过 Flyway 校验。

### 4.4 磁盘与流量

`df -h` 看系统盘。3 Mbps 带宽下，图片和安装包不能走源站。对象存储用量告警留到公开上线前再开。

### 4.5 证书续期

`certbot` 的 systemd timer 会自动续期。每个季度手动看一次：

```bash
systemctl list-timers | grep certbot
```

## 五、版本发布

1. 在构建机执行 `mvn -B verify`，通过后再 `mvn -B -DskipTests package`。
2. 把当前 jar 复制为 `/opt/necoocean-tools/necoocean-tools-backend.jar.prev`。
3. 数据库先按 4.3 备份。
4. 换上新 jar，`sudo systemctl restart necoocean-tools`。
5. 跑 2.8 的清单。

Flyway 只向前迁移。不可逆的脚本上线前必须先有备份。

前端发布同样保留上一份 `dist`：`/var/www/necoocean-tools.prev`。

## 六、故障处理

### 6.1 常见故障

| 现象 | 处理 |
|---|---|
| 启动日志 `Access denied` | 核对 `/etc/necoocean-tools.env` 的账号口令，以及用户是否只允许从 `127.0.0.1` 连接 |
| `Connection refused` 3306 | `systemctl start mysql`，并确认 `bind-address` |
| Hibernate 校验失败 | 不要改成 `update`。看 Flyway 是否没跑到最新版本，修迁移脚本后重启 |
| 全站留言突然都被限流 | 检查 Nginx 是否送出 `X-Forwarded-For`。内网地址不会进限流桶；所有人都变成同一个公网地址才会误伤 |
| 下载一直是 `40405` | 核对 COS 密钥 / 桶名 / 地域；对象是否真的存在；记录是否已 `complete`（`object_status=1`） |

### 6.2 回滚

```bash
sudo systemctl stop necoocean-tools
sudo mv /opt/necoocean-tools/necoocean-tools-backend.jar /opt/necoocean-tools/necoocean-tools-backend.jar.failed
sudo mv /opt/necoocean-tools/necoocean-tools-backend.jar.prev /opt/necoocean-tools/necoocean-tools-backend.jar
sudo systemctl start necoocean-tools
```

**验证**：健康检查恢复，`systemctl is-active necoocean-tools` 为 `active`。

如果新版本已经执行了新的 Flyway 脚本，只换回旧 jar 不够，还要用 4.3 的备份恢复数据库。先确认 `flyway_schema_history` 里是否多了旧 jar 不认识的版本。

前端回滚：

```bash
sudo rsync -a --delete /var/www/necoocean-tools.prev/ /var/www/necoocean-tools/
```

## 七、本机开发

本机是 Windows，MySQL 服务名 `MySQL84`，数据目录配置在 `C:\ProgramData\MySQL\MySQL Server 8.4\`。服务安装目录没有 `mysql.exe`，查库用 JDBC 或别的客户端。

库 `necoocean_tools` 已由应用执行到 V3。2026-09-22 核对结果：服务器版本 8.4.4，`flyway_schema_history` 的 1、2、3 三条 `success` 都是 1，`admin_users.last_failed_at` 存在，预置 4 个分类和 9 条站点配置。

本机口令放在后端仓库的 `config/local.yml`，该文件已忽略。工作目录必须是后端模块，否则这个文件不会被读到。构建前把 `JAVA_HOME` 指到 JDK 17。

没有 Docker 时，`FlywayMigrationTest` 会跳过。上面这条本机核对用来补上这个缺口。
