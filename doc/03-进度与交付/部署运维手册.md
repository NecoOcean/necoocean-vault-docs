## 一、环境要求

| 项 | 要求 |
|---|---|
| 服务器 | 腾讯云轻量应用服务器，上海五区，4C4G，系统盘 40 GB，带宽 3 Mbps |
| 操作系统 | Ubuntu 22.04 或 24.04。**必须是纯净的系统镜像**——不要使用宝塔面板等预装面板镜像：面板会自带一套 Nginx / MySQL（位于 `/www/server/` 而非系统路径）、默认占用 80 与 443，使 §2.2、§2.3、§2.6 的命令无法照做。<br>**判据只看控制台「镜像与应用」区的三行**：`镜像名称`、`镜像类型`（须为 **系统镜像**）、`操作系统`。**不要用「实例名称」判断**——实例名是可任意编辑的标签（轻量实例常沿用购买时的活动名，如 `宝塔Linux面板4yr1`），**重装系统也不会改变它**，据此判断会得出错误结论 |
| JDK | 17。构建机和服务器都要 |
| MySQL | 8.0 及以上。本机已用 8.4.4 跑通 V1～V5 |
| Nginx | 发行版自带的稳定版 |
| Node | 只装在构建前端的电脑上。服务器不装 |
| 对象存储 | 腾讯云 COS，桶必须建在上海。须配置 CORS，密钥用环境变量注入 |

## 二、首次部署

> **ICP 备案尚未通过时**，按 `docs/doc/03-进度与交付/备案期间部署执行单.md` 执行——它把本节动作按「不配 443 / 不签证书 / 只放通 22」重排成可逐条打勾的路径，并补齐每步的验证方式与端口转发联调方法。**命令仍以本节为准。**

### 2.1 服务器初始化

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo mkdir -p /opt/necoocean-tools /var/www/necoocean-tools /var/backups/necoocean-tools
sudo useradd --system --home /opt/necoocean-tools --shell /usr/sbin/nologin necoocean
sudo chown necoocean:necoocean /opt/necoocean-tools
```

**验证**：`timedatectl` 显示 `Asia/Shanghai`；`id necoocean` 能打出系统用户。

### 2.2 依赖安装

```bash
sudo apt-get update
sudo apt-get install -y openjdk-17-jre-headless nginx mysql-server
java -version
mysql --version
nginx -v
```

**验证**：`java -version` 是 17；`systemctl is-active mysql nginx` 都是 `active`。

### 2.3 数据库初始化

口令只写在服务器上，不写进仓库。

```bash
sudo mysql
```

```sql
CREATE DATABASE necoocean_tools CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'necoocean'@'localhost' IDENTIFIED BY '<数据库口令>';
GRANT ALL PRIVILEGES ON necoocean_tools.* TO 'necoocean'@'localhost';
CREATE USER 'necoocean'@'127.0.0.1' IDENTIFIED BY '<数据库口令>';
GRANT ALL PRIVILEGES ON necoocean_tools.* TO 'necoocean'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> ⚠️ **`'necoocean'@'localhost'` 与 `'necoocean'@'127.0.0.1'` 是 MySQL 里两个不同的账号，必须都建。**
> 只建 `'127.0.0.1'` 会导致应用启动失败，报 `Access denied for user 'necoocean'@'localhost' (using password: YES)`、`Error Code: 1045`——**明明口令没错也照样被拒**。
> **原因**：Ubuntu 上 MySQL 8 的 `skip_name_resolve` 默认为 **0（名字解析开启）**，TCP 连接来自 `127.0.0.1` 时会被**反解成 `localhost`**，于是按 host=`localhost` 去匹配账号，而 `@'127.0.0.1'` 那条匹配不上。
> **判据**：`SELECT @@skip_name_resolve;` 返回 `0` 时必须同时建两个账号；返回 `1` 时才只需 IP 那条。**两条都留着最省事**，无论该开关怎么变都能连上。
> 本项目服务器 2026-09-23 实测即为 `0`，且该错误已实际发生一次。

`<数据库口令>` 自己生成，至少 16 位，记到第 2.4 步的环境文件里。仓库里的 `create_database.sql` 只建库，不建账号；上面这段已经包含建库，不必再跑那份脚本。

确认 MySQL 不对外网监听，并按《技术选型与工程结构（方案对比）》的既定决策设置缓冲池。

`bind-address = 127.0.0.1` 是 Ubuntu 上 MySQL 8 的**默认值**（本项目服务器 2026-09-23 实测确认为 `127.0.0.1`，`mysqlx-bind-address` 同），一般无需改动；若你的机器不同，改 `/etc/mysql/mysql.conf.d/mysqld.cnf` 的 `[mysqld]` 段。

缓冲池**另建独立文件**，不要改发行版自带的 `mysqld.cnf`：

```bash
sudo tee /etc/mysql/mysql.conf.d/zz-necoocean.cnf >/dev/null <<'EOF'
[mysqld]
innodb_buffer_pool_size = 1G
EOF
sudo systemctl restart mysql
```

> **`zz-` 前缀的作用**：`/etc/mysql/my.cnf` 通过 `!includedir /etc/mysql/mysql.conf.d/` **按文件名字典序**引入配置，`zz-` 保证本文件排在 `mysqld.cnf` **之后**加载，同名参数以本文件为准；独立成文件还能避免发行版升级时被覆盖。

> **为什么要显式写 `innodb_buffer_pool_size`**：《技术选型与工程结构（方案对比）》按「**JVM 堆 1G + 缓冲池 1G，余量留给系统与 Nginx**」的分配，在 4 GB 机器上定了 **1G**。MySQL 8 的出厂默认值小于此。**本项目数据量极小，跳过这一步不会有可观测的性能差异**；显式写它的价值是让实际运行参数与文档决策一致，避免日后排查内存问题时对不上账。

**验证**：

```bash
ss -ltnp | grep -E '3306|33060'                                                # 只出现 127.0.0.1
sudo mysql -e "SELECT @@innodb_buffer_pool_size/1024/1024 AS buffer_pool_MB;"   # 期望 1024
free -m                                                                         # 记录内存基线，见 §2.4 的堆配置说明
```

表先不要手建，下一步启动应用时由 Flyway 写入。

### 2.4 应用部署

在构建机上，进入后端仓库：

```bash
mvn -B -DskipTests package
```

合并前仍要先跑一次 `mvn -B verify`。上传的是 `target/necoocean-tools-backend-0.1.0-SNAPSHOT.jar`。

```bash
scp target/necoocean-tools-backend-0.1.0-SNAPSHOT.jar <服务器用户>@<服务器地址>:/tmp/necoocean-tools-backend.jar
```

在服务器上：

```bash
sudo install -o necoocean -g necoocean -m 640 /tmp/necoocean-tools-backend.jar /opt/necoocean-tools/necoocean-tools-backend.jar
```

先补一个管理员口令：

```bash
openssl rand -base64 18
```

然后在**环境变量里放全部真值**，再用**不带引号的 heredoc** 展开写入：

```bash
DBPASS='<数据库口令>'
SALT='<IP_HASH_SALT>'
ADMINPW='<管理员口令>'
COSID='<子用户 SecretId>'
COSKEY='<子用户 SecretKey>'
BUCKET='<桶名>'
ORIGINS='<前端 Origin>'

sudo tee /etc/necoocean-tools.env >/dev/null <<EOF
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://127.0.0.1:3306/necoocean_tools?characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
DB_USERNAME=necoocean
DB_PASSWORD=$DBPASS
IP_HASH_SALT=$SALT
ADMIN_USERNAME=admin
ADMIN_PASSWORD=$ADMINPW
COS_PROVIDER=tencent
COS_REGION=ap-shanghai
COS_BUCKET=$BUCKET
COS_SECRET_ID=$COSID
COS_SECRET_KEY=$COSKEY
COS_CORS_ORIGINS=$ORIGINS
COS_CORS_AUTO_APPLY=true
EOF
sudo chmod 600 /etc/necoocean-tools.env
unset DBPASS SALT ADMINPW COSID COSKEY BUCKET ORIGINS
```

**验证**（第二步会一并验出占位符是否残留）：

```bash
sudo grep -c '<' /etc/necoocean-tools.env     # 期望 0
sudo grep -c '=' /etc/necoocean-tools.env     # 期望 14
sudo ls -l /etc/necoocean-tools.env           # 期望 -rw------- root root
```

> ⚠️ **为什么写成「变量 + 不带引号的 heredoc」**：直接粘一个带 `<占位符>` 的 heredoc 极易**整体照抄而忘记替换**——本项目 2026-09-23 实际发生过一次，结果是 `DB_PASSWORD=<数据库口令>` 原样入库，应用报 `Access denied`（口令"填了"却是错的），排查成本远高于当初省下的几秒。改成变量后，**文件正文里根本不存在占位符**，`sudo grep -c '<'` 返回 0 才算写对。
> 注意 `<<EOF` **不加引号**才能让 `$DBPASS` 被 shell 展开；base64 值只含字母数字与 `+/=`，不含 `$` 或反引号，展开是安全的。

> ⚠️ **`COS_CORS_ORIGINS` 在生产是必填项，不能省。** 它的**默认值只含本机开发地址**（`http://127.0.0.1:5173` 等四个），**不含任何生产域名**。而应用启动时会**用这个列表整体替换**对象存储桶上的 CORS 规则（见 §3.3）——不填的后果是：**桶上原本正确的 CORS 被替换成一份只允许本机地址的规则，浏览器直传在生产域名下全部报 `Failed to fetch`**。多个来源用逗号分隔，例如 `https://<域名>`；若本机也要联调，可写成 `https://<域名>,http://localhost:5173`。

> ⚠️ **每一项都必须是合法的 Origin，两条硬规则**：① **必须带协议**（`http://` / `https://`）——写成 `localhost:80`、`1.15.15.135` 这种缺协议的值会让**整条规则形同不存在**；② **默认端口不写**——浏览器访问 `http://localhost:80` 时发出的 Origin 是 **`http://localhost`**（`:80` 被规范化掉），把它当成 Origin 去配就永远匹配不上。
> **取值纪律**：在已打开本站的浏览器里按 `F12` → Console → 输入 **`location.origin`**，用它的输出，不要手拼、不要猜端口。
> **2026-09-23 首次部署实测踩此坑**：填成 `localhost:80`，浏览器直传报 `fetch` 的 `TypeError`；`curl -X OPTIONS` 带 `Origin` 复现时返回 **403 且无任何 `Access-Control-Allow-*` 头**。**判据**：前端「直传 COS 失败（多为桶未配置 CORS）」这句对应 `fetch` 抛 `TypeError`，即**请求被浏览器拦在网络层、未拿到响应**；预签名不匹配 / 权限不足 / 桶名错误都会回具体状态码，前端显示的是 `COS 上传失败 HTTP 4xx`。

> **`COS_CORS_AUTO_APPLY`** 默认 `true`，即启动时自动写入桶 CORS。若你的 CAM 子用户**不含 `PutBucketCORS`** 权限，设成 `false` 并改在控制台手工维护 CORS 规则。

`<管理员口令>` 长度 8～72。库里已经有管理员之后，再改这个值不会覆盖原口令。`<随机长字符串>` 用来和客户端 IP 拼接后做 SHA-256，生产环境不要用开发默认值 `dev-only-ip-salt`。

> ⚠️ **缺 `COS_*` 不会让应用启动失败，却会让对象存储静默失效**。`COS_REGION` / `COS_BUCKET` / `COS_SECRET_ID` / `COS_SECRET_KEY` 四项在配置里**都没有默认值**，缺任一项时 provider 降级为 `Unavailable`：**上传接口与下载签名全部不可用，而进程照常启动**，故障只在功能层面暴露。对照关系：`IP_HASH_SALT` 在 `prod` 下**无默认值且缺失即启动失败**（行为与 `COS_*` 相反）。`COS_REGION` 必须与服务器同在上海（见 §3.3）。

```bash
sudo tee /etc/systemd/system/necoocean-tools.service >/dev/null <<'EOF'
[Unit]
Description=NecoOcean tools API
After=network.target mysql.service

[Service]
User=necoocean
Group=necoocean
WorkingDirectory=/opt/necoocean-tools
EnvironmentFile=/etc/necoocean-tools.env
ExecStart=/usr/bin/java -Xmx1g -jar /opt/necoocean-tools/necoocean-tools-backend.jar
Restart=on-failure
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now necoocean-tools
```

> **`-Xmx1g` 的来历**：《技术选型与工程结构（方案对比）》规定 4 GB 机器上给应用堆上限 **1G**，剩余约 2 GB 留给 MySQL、系统与 Nginx；**切勿把堆开到 2 GB 以上**，否则 MySQL 与系统易被 OOM Killer 命中。JVM 的 ergonomics 在 4 GB 机器上算出的默认上限恰好也接近 1G，**但那是巧合、不是约定**——显式写死才能与 §2.3 的缓冲池分配共同构成一份可核对的预算（1G 堆 + 1G 缓冲池 + 约 2G 系统/MySQL/Nginx）。

**验证**：`systemctl status necoocean-tools` 为 `active (running)`。日志里出现 Flyway `Successfully validated` 或 `Successfully applied`，并且没有 Hibernate 校验失败。然后：


返回 JSON，且 `code` 为 0。

### 2.5 前端部署

前端仓库 `necoocean-tools-frontend` 已建立（Vue 3 + Vite）。在本地构建，不要在服务器上装 Node：

```bash
npm run build
scp -r dist <服务器用户>@<服务器地址>:/tmp/necoocean-frontend
```

> **不要写成 `dist/*`**：在 Windows PowerShell 下通配符不会为原生命令展开，`*` 会被**字面**传给 `scp` 导致报错。传整个目录即可——`scp -r dist <目标不存在>` 会把 `dist` 的内容放进目标目录，结果与预期一致。

```bash
sudo rsync -a --delete /tmp/necoocean-frontend/ /var/www/necoocean-tools/
```

**紧接着必须修正属主与权限。** `rsync -a` 会**保留源文件的属主与权限**（`-a` 含 `-o -g -p`），而源目录是 `scp` 以普通用户身份创建的——结果是**网站根目录变成普通用户所有，权限还可能是 `0707`（others 可写）**。本项目 2026-09-23 实测即得到 `drwx---rwx ubuntu ubuntu`。

```bash
sudo chown -R root:root /var/www/necoocean-tools
sudo find /var/www/necoocean-tools -type d -exec chmod 755 {} \;
sudo find /var/www/necoocean-tools -type f -exec chmod 644 {} \;
```

> Nginx 以 `www-data` 身份读取，靠的是 755/644 的 **other 位**：**不需要**把目录给 `www-data` 所有，也**不应该**让 others 可写。

构建产物是纯静态文件（`index.html` + `assets/`），不含服务端逻辑；生产环境由 Nginx 同源分发，**不启用 CORS**。

**验证**：

```bash

find /var/www/necoocean-tools -perm -o=w -print    # 期望无输出（others 不可写）
du -sh /var/www/necoocean-tools/                   # 与本地 dist/ 体积相符
```

### 2.6 Nginx 配置

```bash
sudo tee /etc/nginx/sites-available/necoocean-tools >/dev/null <<'EOF'
server {
    listen 80;
    server_name <域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name <域名>;
    ssl_certificate /etc/letsencrypt/live/<域名>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<域名>/privkey.pem;

    root /var/www/necoocean-tools;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;
    gzip_comp_level 6;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /download/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
sudo ln -sfn /etc/nginx/sites-available/necoocean-tools /etc/nginx/sites-enabled/necoocean-tools
sudo nginx -t && sudo systemctl reload nginx
```

> 必须把 `X-Forwarded-For` 传给应用，应用只取第一段。缺了这个头，或者第一段是内网地址时，留言限流会跳过该请求，不会把所有访客算进同一个桶。

> ⚠️ **`gzip_types` 里不要写 `text/html`**：Nginx **始终**压缩 `text/html`（默认隐含），再列一次会触发 `nginx: [warn] duplicate MIME type "text/html"`。该 warning **不影响功能**（`nginx -t` 仍返回 successful），但会污染每次 `nginx -t` 的输出——本项目 2026-09-23 实测踩到，已从上面的配置中移除。

> ⚠️ **`http2` 的写法随 nginx 版本而变，写错会让 `nginx -t` 直接失败。** Ubuntu 22.04 软件源里的 nginx 是 **1.18.0**（2026-09-23 在本项目服务器上实测 `nginx -v` 得到），此时**只能**写成 `listen 443 ssl http2;`——本文已按此写法。而 `http2 on;` 这个**独立指令自 nginx 1.25.1 才引入**，在 1.18 上会报 `unknown directive "http2"`。若日后升级到 ≥ 1.25.1，两种写法皆可用，以 `nginx -t` 通过为准。本写法与 `docs/doc/02-设计与实现/前后端分离架构说明.md` §七 一致。

> **IPv6 注意事项**：上面的 `listen 80;` 与 `listen 443 ssl http2;` **只监听 IPv4**。腾讯云轻量实例默认开启 IPv6，若不加处理，**IPv6 访客无法访问本站**。二者择一：① 在控制台关闭实例的 IPv6；② 在两个 `server` 块的 `listen` 后各补一行 `listen [::]:80;` / `listen [::]:443 ssl http2;`。应用侧限流**已支持 IPv6 地址**（`ClientIpHasher.isPublicIpv6`），无需改代码。

证书还没签发时，先不要启用上面的 443 段。本机调试继续用 `http://127.0.0.1:8080`。

**验证**：`sudo nginx -t` 显示 `syntax is ok`。

### 2.7 HTTPS 证书

一期不公开时可以不做。要公开时：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d <域名>
```

**验证**：`sudo certbot renew --dry-run` 成功。

> ⚠️ **顺序约束：证书必须等 ICP 备案通过之后再签。** `certbot --nginx` 默认走 **HTTP-01** 验证，要求 `<域名>` 已解析到本机且**外网能经 80 端口访问到它**；而大陆地域实例在备案通过前，80 / 443 的对外 Web 访问会被拦截，验证必然失败。**备案未通过时不要反复尝试签证书**（Let's Encrypt 有失败频率限制）。同理，备案前也不要用 `http://<域名>/` 做联调——先按 §2.8 在服务器本机用 `curl http://127.0.0.1:8080/...` 逐项验证。

### 3.1 环境变量

| 变量 | 作用 | 缺了会怎样 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 生产设为 `prod` | 会带上开发默认值 |
| `DB_URL` | JDBC 地址 | `prod` 下启动失败 |
| `DB_USERNAME` | 数据库账号 | `prod` 下启动失败 |
| `DB_PASSWORD` | 数据库口令 | `prod` 下启动失败 |
| `IP_HASH_SALT` | IP 哈希盐 | `prod` 下启动失败 |
| `ADMIN_USERNAME` | 首次创建的管理员名，默认 `admin` | 使用默认名 |
| `ADMIN_PASSWORD` | 仅在管理员表为空时创建账号 | 打一行日志后继续启动，不创建账号 |
| `COS_PROVIDER` | `tencent`（默认）或 `memory`（仅测试） | 默认腾讯云 |
| `COS_REGION` | 桶地域，须 `ap-shanghai` | 无法签发预签名 |
| `COS_BUCKET` | 桶名，**须为 `name-appid` 形式**（如 `necoocean-vault-1381419798`）。**取值以控制台「复制」按钮取得的文本为准，不要手抄、不要按截图转录**；本机 `necoocean-tools-backend/config/local.yml` 的 `COS_BUCKET` 是可互相印证的机器可读来源 | 无法签发预签名；**名字错一位即报 `NoSuchBucket` (404)**，且异常被捕获后只记 error、不影响启动，容易长期潜伏 |
| `COS_SECRET_ID` | 子用户 SecretId | 无法签发预签名 |
| `COS_SECRET_KEY` | 子用户 SecretKey | 无法签发预签名 |
| `COS_CORS_ORIGINS` | 浏览器直传允许的 Origin，逗号分隔 | **不报错**，但默认值只含本机地址；启动时会用它**整体替换**桶上 CORS 规则，导致生产域名直传全部 `Failed to fetch` |
| `COS_CORS_AUTO_APPLY` | 启动时是否自动把 CORS 写入桶，默认 `true` | 使用默认值（自动写入）；子用户无 `PutBucketCORS` 时启动日志会报 error，但**不影响启动** |

### 3.2 数据库连接

生产账号只用 `necoocean`@`127.0.0.1`，不要用 `root`。字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`。Flyway 需执行到 **V5**（含 `export_audit_logs`）。

### 3.3 对象存储

桶建在上海，和服务器同地域。私有读写；上传预签名 60 分钟，下载预签名 5 分钟。密钥只放环境变量或已忽略的 `config/local.yml`，**不要进仓库**。**四项 `COS_*` 连接参数须齐全，取值来源与缺失后果见 §2.4。**封面上传接口一期未实现，`cover_url` 恒为 `null`（详见 `docs/doc/02-设计与实现/验收用例集.md` §4.5）。

**CORS 由应用在启动时自动写入**（`TencentCosObjectStore` 构造函数调用 `ensureBrowserCors()`）：

| 项 | 行为 |
|---|---|
| 触发条件 | `COS_CORS_AUTO_APPLY=true`（默认）且 `COS_CORS_ORIGINS` 非空 |
| 写入内容 | 规则 id `necoocean-browser-upload`；方法 `PUT/GET/HEAD/POST`；允许头 `*`；暴露头 `ETag, Content-Length, x-cos-request-id`；有效期 3600 秒 |
| ⚠️ 替换语义 | 调的是 `setBucketCrossOriginConfiguration`，**整体替换桶上已有的全部 CORS 规则**，不是追加。故**不要在控制台与应用两处同时维护**，否则每次启动都会被覆盖 |
| 权限要求 | CAM 子用户须具备 **`PutBucketCORS`**（桶级配置写权限），比对象级读写更宽 |
| 失败行为 | **只写 error 日志，不抛异常、不阻塞启动**；日志会提示「浏览器上传将表现为 Failed to fetch」 |
| 手工替代 | 设 `COS_CORS_AUTO_APPLY=false` 并改在控制台维护 CORS |

## 六、故障处理

### 6.1 常见故障

| 现象 | 处理 |
|---|---|
| 启动日志 `Access denied` | 核对 `/etc/necoocean-tools.env` 的账号口令，以及用户是否只允许从 `127.0.0.1` 连接。**注意 MySQL 里 `'necoocean'@'localhost'` 与 `'necoocean'@'127.0.0.1'` 是两个账号，两个都要建**（见 §2.3） |
| 后台登录报「账号或密码错误」，而 env 里的 `ADMIN_PASSWORD` 看着是对的 | ① **先确认不是拿本机 `config/local.yml` 的口令来登服务器**（两套环境的口令不同，这是实测踩过的混淆）；② **改 env 不会重置已有口令**——`AdminAccountInitializer` 在 `admin_users` 非空时**直接返回**。重置办法：`sudo mysql -e "DELETE FROM necoocean_tools.admin_users;"` 后 `sudo systemctl restart necoocean-tools`，初始化器会按当前 env 的 `ADMIN_PASSWORD` 重建（⚠️ 若 `message_replies` 已有数据，可能受外键约束，需先处理）；③ 确认账号创建过一次：`grep 'admin account created' /opt/necoocean-tools/logs/necoocean-tools.log`——若只有 `admin account not created, ... is unset`，说明当时 `ADMIN_PASSWORD` 为空，根本没建号 |
| `Connection refused` 3306 | `systemctl start mysql`，并确认 `bind-address` |
| Hibernate 校验失败 | 不要改成 `update`。看 Flyway 是否没跑到最新版本，修迁移脚本后重启 |
| 全站留言突然都被限流 | 检查 Nginx 是否送出 `X-Forwarded-For`。内网地址不会进限流桶；所有人都变成同一个公网地址才会误伤 |
| 下载一直是 `40405` | 核对 COS 密钥 / 桶名 / 地域；对象是否真的存在；记录是否已 `complete`（`object_status=1`） |

### 6.2 回滚

## 七、本机开发
