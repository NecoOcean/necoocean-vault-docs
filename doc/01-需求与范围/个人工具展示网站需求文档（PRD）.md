## 一、项目概述

### 1\.1 项目背景

本人自主开发多款轻量化工具产品，包含移动端APP、Python脚本、桌面小工具等，目前无统一公开展示、分发、反馈渠道。为集中沉淀个人开发成果、方便用户获取工具资源、高效收集用户使用反馈与BUG问题，需搭建专属个人工具展示网站，实现工具展示、下载、专题介绍、留言交互一体化功能。

### 1\.2 项目目标

- 集中展示个人所有原创小工具，分类清晰、查阅便捷，打造个人技术作品展示主页；

- 后台支持各类工具资源文件的上传、归档与多版本管理；前台提供原始文件的直接下载，适配 APP、Python 脚本等多类型文件。本站**不提供**文件的在线预览、在线编辑、格式转码与在线运行能力（依据 ADR-001）；

- 为每一款工具独立生成专属专题页面，承载工具介绍、更新日志、资源下载、用户留言功能；

- 搭建轻量化留言反馈系统，支持用户提交使用体验、功能建议、BUG报错、问题咨询，实现高效用户调研与问题收集；

- 整体页面简洁轻量化，无冗余功能，聚焦工具展示与用户交互，适配电脑、手机端访问。

### 1\.3 目标用户

工具使用者、技术爱好者、同行开发者、普通体验用户。

## 二、核心需求与功能模块

网站整体分为**前台用户展示交互端**和**后台管理员管理端**两大模块，核心围绕工具展示、专题页面、留言反馈、资源管理四大核心能力展开。

### 2\.1 前台核心功能（用户访问端）

#### 2\.1\.1 首页模块

- **个人主页介绍**：展示个人简介、开发简介、网站定位（个人原创工具合集、免费分享、持续更新）；

- **工具总览展示**：以卡片形式展示所有已上架工具，卡片包含工具名称、缩略图、简介、更新时间、分类标签；

- **分类筛选**：支持按工具类型筛选（APP应用、Python脚本、桌面工具、其他工具）；

- **搜索功能**：支持关键词搜索工具名称、功能简介，快速定位对应工具；

    - **匹配范围与规则**：匹配 `name` 与 `summary` 两个字段，采用**不区分大小写的包含匹配**；不检索 `tutorial`（长文本会拖慢查询且对定位工具帮助有限）；

    - **与分类筛选的叠加关系**：搜索与分类筛选**可同时生效，取交集（AND）**——即"在选定分类内搜索"。两者任一为空则仅按另一条件过滤；两者均为空则返回全部已上架工具；

- **快捷入口**：每个工具卡片可直接跳转至对应工具专属专题页面。

#### 2\.1\.2 工具专属专题页面（核心功能）

网站核心模块，**每一款工具独立对应一个专属专题页面**，页面内容独立、链接独立，功能统一标准化，具体包含以下内容：

- **工具基础信息展示**：工具名称、工具封面图、最新版本、更新时间、适用平台（Windows/Android/Mac/通用）、功能简介、详细使用教程；**开发时间**为选填展示字段（A-20），填写后与"更新时间"并列展示，留空则该项不显示；

- **版本更新日志**：记录每一次版本迭代内容，包含新增功能、功能优化、BUG修复说明；一条日志对应一个版本号；

- **资源下载区**：支持多版本文件并存展示，用户可直接下载对应工具安装包、脚本源码、使用配置文件，显示文件名、文件大小、上传时间、适用平台、版本号与 SHA-256 校验值。

    - 单文件大小上限与允许的文件类型按 4.3 执行；

    - 对 Web 型工具、代码仓库等**外链型资源**，仅提供站外跳转链接，不在站内嵌入运行或代理内容；

    - 本区**不提供**任何形式的文件预览（含 PDF/图片/文本预览、压缩包目录浏览），**不提供**在线编辑、转码与在线运行；

- **用户留言反馈区**（核心交互功能）：

    - 公开留言板块，所有访问用户均可查看留言内容（一期先发后审，留言提交后即时公开；二期切换先审后发后改为"审核通过后展示"，见 9.3）；

    - 用户无需注册登录即可留言（降低反馈门槛）；

    - **留言分类**：提交时须选择分类——使用体验、功能建议、BUG报错、问题咨询；

    - 留言内容包含：昵称（可自定义匿名）、**邮箱（选填，仅管理员可见）**、留言分类、留言内容、提交时间；

    - **BUG 类留言的结构化字段**：当分类选择"BUG报错"时，追加以下字段，用于问题定位：

        - 运行平台／系统版本（选填，如 Windows 11 / Android 14）；

        - 所使用工具版本（选填，前端默认带出该工具当前推荐版本，可由用户修改）；

        - 复现步骤（选填，多行文本）；

    - 管理员可在前台回复用户留言，形成问答交互。**一期回复方仅为管理员，访客不可对留言二次回复**（避免评论线程化与审核成本；如需访客追评另行提出）；

    - 支持留言分页展示，**每页默认 20 条、上限 100 条**（传参超限按 100 截断），默认按提交时间倒序（最新在前）；管理员置顶的留言优先展示，多个置顶之间按提交时间倒序；

    - **已知限制**：一期不提供回复通知。用户不会收到"你的留言已被回复"的提示，需自行回访查看。该能力列入二期（见 6.2）。

#### 2\.1\.3 全站通用功能

- 响应式布局：适配PC端、手机端、平板端浏览；

- 页面导航：固定顶部导航栏，包含首页、全部工具（跳转首页工具区）、关于我；

- 底部信息：展示网站简介、版权信息、隐私政策入口、**ICP 备案号**（若站点未完成备案则不展示该项，见 9.1）。

### 2\.2 后台核心功能（管理员操作端）

#### 2\.2\.1 工具管理功能

- **新增工具**：自主添加新工具，填写工具名称、简介、详情教程、分类、版本信息、上传封面图、上传资源文件；

- **编辑工具**：修改工具所有信息、更新版本日志、替换/新增下载资源、修改封面图；

- **下架/删除工具**：支持临时下架工具（隐藏前台展示）或永久删除工具及对应专题页面；

- **工具分类管理**：维护分类（APP、Python脚本、桌面工具等），支持新增、编辑、删除分类；

- **存储占用查看**：可查看每个工具占用的存储空间（对象存储用量），可删除历史版本文件；

#### 2\.2\.2 留言反馈管理功能

- **留言总览**：集中查看所有工具的用户留言，可按对应工具、留言时间、留言分类、留言状态、**是否留有邮箱**筛选；

- **留言操作**：支持回复留言、删除恶意留言、置顶重要反馈（高频BUG、优质建议）；

- **留言详情**：查看留言的完整字段，**含邮箱（仅此处可见）**，可一键复制或直接发起邮件；同时展示 BUG 类留言的平台、版本与复现步骤；

- **反馈统计**：查看各工具留言数量、BUG反馈数量、建议数量（一期仅做数量计数，可视化面板属二期）；

- **留言状态管理**：可标记留言状态（未处理、已处理、已跟进、无需处理），方便跟进问题。

#### 2\.2\.3 网站基础设置

- 首页个人简介、网站标题、版权信息修改；

- 后台账号密码修改、登录权限管控；

- 网站基础开关（留言功能开启/关闭）。**关闭语义（已定，Q-5）**：前台隐藏留言提交表单，后端拒绝新留言提交并返回明确错误码；**既有留言与管理员回复仍保持可见**——不得因关闭开关而隐藏或删除历史反馈；

- **"关于我"页面内容与隐私政策内容编辑**（HTML 或 Markdown 富文本，见 3、6.1）。

> 注：原"新留言提醒"开关已移除。该功能属二期（见 6.2），一期保留开关会造成与开发范围不符的预期。
>
> 注：**轮询间隔不设后台配置项**，固定为 30 秒（见 4.1）。原表述"作为可配置项"已作废，避免为一个低价值参数增加设置项与接口。
>
> 注：**留言审核模式**属预留配置项（见 9.3）。一期固定为"先发后审"，后台不暴露切换入口；内部以配置项形式存放，供二期更新时切换。

### 2\.3 留言邮箱字段的可见性约束（强制）

- 公开留言列表接口**必须在后端序列化阶段白名单输出，不得返回 `contact_email` 字段**。此约束不可通过"前端不渲染"实现；

- 邮箱仅在后台管理端（需登录）可见；后台留言**列表页默认不展示邮箱**，仅详情页展示。列表页可展示 `has_email`（是否有邮箱）布尔标识，但不得展示邮箱本身；

- 数据导出默认不含邮箱列，需管理员**显式勾选**"包含邮箱"方可导出；导出动作须留审计记录（操作人 + 时间 + 是否含邮箱）（A-19 定稿）；

- 详细定义与实现约束见 ADR-002；接口层落点见 `docs/doc/02-设计与实现/附录C-接口清单与统一约定.md` 的 C-06 / C-34 / C-35。

### 2\.4 站点配置项的存储与编辑范围

- **可后台编辑的站点配置**：网站标题、首页个人简介、版权信息、ICP 备案号、"关于我"页面内容、隐私政策页面内容、留言功能开关、留言审核模式（预留，一期不暴露）；

- 上述配置以**键值对**形式存储于独立配置表（见 8.8 `site_settings`），新增配置项无需改动表结构；

- 编辑内容支持 Markdown 或受限 HTML（**须做 XSS 过滤**，禁止 `<script>`、事件属性、`iframe` 等）；渲染时作为页面正文而非可执行内容。

## 三、页面架构整体规划

网站采用**严格前后端分离**模式：**前端独立项目**（Vue 3）负责全部页面与交互，**后端独立服务**（Spring Boot）**仅通过 HTTP API 提供 JSON 数据**，不含模板引擎、不输出任何页面。二者以附录C 的接口契约协作。整体页面结构清晰，层级简单，具体如下：

> 架构、目录结构与部署方式详见 `docs/doc/02-设计与实现/前后端分离架构说明.md`。部署采用**同源部署**（同一域名，前端走 `/`、API 走 `/api/v1/`），因此不启用 CORS。

1. **首页**：个人介绍 \+ **全量工具卡片总览** \+ 分类筛选 \+ 搜索

    > 一期**不单独设立"全部工具列表页"**。当前工具数量少，首页即承载全量列表与筛选（依据《待确认参数台账》A-8）。导航栏"全部工具"跳转至首页工具区。待工具数量增长后再拆分为独立列表页，届时首页改为展示精选／最新 N 个。

2. **工具专题详情页（N个）**：单工具专属页面，包含详情、日志、下载、留言区

3. **关于我页面**：个人开发经历、作品汇总、联系方式、网站说明

4. **隐私政策页**：留言信息收集说明、免责声明

5. **后台管理页**：工具管理、留言管理、网站设置（独立登录入口）

## 四、交互规则与细节要求

### 4\.1 工具专题页交互规则

- 每个工具专属URL独立、固定，可单独分享、收藏；URL 标识（slug）在创建后不随工具名称变更；

- 专题页内容由后台数据统一渲染，无手工同步环节；工具更新后前台展示随之变化；

- 下载按钮清晰醒目，点击直接触发文件下载，无多余跳转；

- **留言刷新规则**：留言提交成功后即时插入当前页面（无需等待轮询）；其他访客的新留言通过页面刷新或轮询获取，**轮询间隔固定为 30 秒**（客户端常量，不设后台配置项——低价值参数不值得为此增加设置项与接口，A-4 已定稿）；一期不引入 WebSocket 等长连接方案；

- 留言默认按提交时间倒序排列，管理员置顶的留言优先展示；管理员回复公开可见。

### 4\.2 留言反馈交互规则

- 用户无需注册、无需登录，输入昵称\+留言内容即可提交；邮箱为**选填**字段，留空不影响提交；

- **邮箱字段定义**：它是可选联系渠道，**不是账号**——不用于登录、不作为用户唯一标识、不做跨留言去重；**对访客不公开**（含提交者本人）；用途严格限定于就本次留言进行问题跟进与处理结果告知，不得用于营销或其他二次触达；

- **标准文案**（须与前台表单、隐私政策页保持一致，不得出现多种说法）：

    - 字段标签：`邮箱（选填）`

    - 字段说明：`仅管理员可见，用于向你反馈问题处理结果，不会公开显示。`

    - 格式错误提示：`邮箱格式不正确，可留空。`

- 邮箱校验以后端为准，长度不超过 254 字符；一期**不发送验证邮件**，也不发送任何通知邮件（因此该字段不构成垃圾邮件入口）；

- **限流（已定值）**：同一 IP 哈希维度 **60 秒内最多提交 5 条**留言，自第 6 条起拒绝并提示"提交过于频繁，请稍后再试"（阈值严格小于 B-14 用例的 10 条触发线）；限流以 IP 哈希为维度，不存储明文 IP；

- **关键词行为（一期口径）**：关键词**不拦截、不阻止公开**——命中即在留言上打 `keyword_flagged` 标记（字段见 8.5），并在后台"待复核"队列优先展示，由管理员复核后决定保留或删除（与 9.3 分期策略一致）；

- **内容长度上限（前后端双重校验，后端为准）**：留言内容 ≤2000 字；复现步骤 ≤1000 字；昵称 ≤50 字；BUG 类留言的运行平台 ≤50 字、工具版本 ≤32 字。超出即拒绝提交并给出明确提示（上限与 8.5 字段定义一致）；

- 所有留言绑定对应工具，后台可精准区分哪款工具的用户反馈；

- 支持匿名留言，用户可自定义昵称或填写"匿名"；邮箱不得作为身份标识展示，也不得用于自动生成昵称；

- 删除留言时，该条留言的邮箱随记录一并删除，不单独留存。

### 4\.3 资源上传下载规则

- **允许上传的文件类型（白名单，扩展名与 MIME 双重校验）**：`.apk` `.exe` `.msi` `.dmg` `.zip` `.7z` `.rar` `.py` `.tar.gz` `.pdf` `.txt` `.md` `.json` `.yaml` `.ini` `.cfg` `.whl` `.AppImage` `.deb`；
    > **2026-09-21 补充**：追加 `.whl`（Python 轮子包）、`.AppImage`（Linux 便携可执行）、`.deb`（Debian 系安装包）三类。已复核安全性——`.whl` 为 zip 容器、`.deb` 为 ar 归档、`.AppImage` 为 ELF 可执行体，**三者均不会被浏览器内联解析执行**，与拒绝列表中的脚本类文件性质不同。MIME 校验对应值：`.whl` → `application/zip`、`.deb` → `application/vnd.debian.binary-package`、`.AppImage` → `application/octet-stream`。

- **显式拒绝的类型**：`.html` `.htm` `.svg` `.js`（可致存储型 XSS）与 `.php` `.jsp` `.asp` `.sh` `.bat` `.cmd`（服务端可执行类型）；

- **单文件大小上限**：200 MB（已确认）。超出即拒绝上传并给出明确提示；

- **工具封面图（独立规则，不走资源文件通道）**：仅允许 `.jpg` `.jpeg` `.png` `.webp` 四种格式，单张 ≤2 MB；对象键形如 `covers/{tool_id}/{uuid}.{ext}`。封面图需公开访问（首页卡片与专题页展示），因此**仅 `covers/` 前缀开启公开读**，存储桶其余部分仍为私有读写（见 5.3）；封面图由 CDN 公开 URL 直接引用，不经 `/download/{file_id}` 302 跳转；

- **上传方式（两阶段）**：后端先签发预签名上传凭证（签发时预校验扩展名与大小上限，凭证有效期 **60 分钟**），前端直传对象存储，避免 200 MB 文件经过应用服务器的内存与磁盘；直传完成后前端回调确认，后端落库对象键与文件元信息。超时未回调确认的上传记录在后台"存储占用"页标记为异常并定期清理（见 2.2.1）；

- **SHA-256 核验（已确认方案 A：信任前端回传 \+ 格式校验，A-12）**：校验值由前端在直传完成后计算回传，后端仅校验格式（64 位小写十六进制）后落库，**不回拉对象重新计算**（避免 200 MB 回传流量与算力开销）。已知限制：校验值真实性依赖前端，**管理员上传重要文件后应自行下载核对一次**；不得以对象存储 ETag 冒充 SHA-256 对用户展示；

- 支持多版本文件并存展示，用户可按需下载旧版本/最新版本；文件展示 SHA-256 校验值，并在下载区公示"文件由作者本人打包上传，下载后请自行核对校验值"；

- **下载链接不得暴露对象存储的真实路径**。统一经后端接口 `/download/{file_id}` 校验后，返回 302 重定向至带时效的 **COS 预签名地址**（**下载签名有效期 5 分钟**；与上传凭证的 60 分钟区分；接入 CDN 后改为 CDN 签名地址，地址来源由配置项切换）。下载计数在重定向环节累加。对象存储桶须为**私有读写**，禁止开启公开读；

- 文件缺失（数据库有记录、对象存储中无对象）时返回明确的 404 提示，并在后台标记为"异常文件"，不做静默失败；

- **对象存储地域须与轻量服务器一致（上海）**。COS 按"单账号单地域"计算配额，且跨地域访问会产生**跨地域流量费**并增加回源延迟——建桶时选错地域是实施阶段最常见的疏漏，须在部署前核对；

- **存储与分发方案（已确认）**：文件存放于**对象存储（腾讯云 COS）**，**一期经预签名直链分发；正式公开前接入 CDN**（届时仅需更换访问域名与配置防盗链，**不改业务代码**）。下载流量不占用服务器带宽，因此 5.1 中"页面加载延迟≤1.5s"不再受文件下载影响，也**不受服务器 3 Mbps 带宽约束**（见 9.1）。需注意四点：① CDN 与对象存储按流量计费，须配置费用告警与用量监控；② CDN 须配置防盗链（Referer 白名单）并结合签名 URL 的时效性，避免流量被第三方盗用；③ **一期暂不接入 CDN**（一期不上线、访问量极低）；④ 已购容量包**仅抵扣存储容量，不含外网下行流量**，下行流量单独计费，须设置用量告警；

- 下载无广告、无付费、无强制跳转，免费公开获取。

## 五、非功能需求

### 5\.1 性能需求

- 页面加载速度快，静态资源轻量化：**首页与工具专题页首屏完整加载时间 P75 ≤1.5s**（度量口径：常规家用宽带环境，首次访问、无 CDN 缓存命中加成）。

    > ⚠️ **达标边界（前后端分离 \+ 3 Mbps 源站下必须遵守）**：首屏资源预算 gzip 后 **≤163 KB**（JS ≤130 / CSS ≤15 / HTML ≤3 / 首屏 API ≤15）。在源站 3 Mbps（约 375 KB/s）总出网带宽下，理论传输耗时为：并发 1 人 0.42s、3 人 1.27s、5 人 2.12s、10 人 4.24s（未计 RTT 与 JS 执行）。因此该指标的**达标场景为并发峰值 ≤3 人**；超出时须执行《前后端分离架构说明》§8 阶段 1（前端产物迁 COS 静态托管，源站只承载 API），届时本指标重新评估。
    >
    > **✅ 已定稿（2026-09-21，NecoOcean 确认）**：本口径照此执行，不再变更。

- 并发能力（**接口层**）：**≥50 并发用户**请求 API 时错误率 **<1%**，无数据错乱（留言列表不出现串页、重复或丢失）。

    > 该指标针对 **JSON 接口**（单次响应 gzip 后约数 KB），与上面的"首屏加载"是两件事——两者不得混为一谈，一期不做 50 人同时加载页面的压测（该场景在当前带宽下不成立）。
    >
    > ⚠️ **口径限定（前后端分离 + 3 Mbps 源站下必须遵守）**："50 并发用户"定义为**持续请求节奏下的虚拟用户数**（每个用户按典型浏览节奏发起请求），**不得理解为"50 个用户的全部请求在同一瞬间返回"**。前者在源站带宽下成立（50 用户分散请求，峰值约数百 KB/s）；后者需要 50 次响应在 1 秒内出网（≥500 KB），超过 384 KB/s 的管道能力，**在阶段 1 完成前不可验收**。压测脚本须按此口径编写。

- 文件下载经 **COS 预签名直链**分发（一期不接 CDN），不占用应用服务器带宽与进程；页面资源与文件下载互不争抢。

### 5\.2 视觉需求

- 整体风格简约、干净、极简直白，偏向技术风、个人开发者风格；

- 无花哨动画、无冗余装饰，重点突出工具内容、下载入口、留言区；

- 配色统一，排版规整，阅读体验舒适。

### 5\.3 安全需求

- 后台登录加密，防止非法访问；登录失败次数限制，单管理员账号；

- 留言内容关键词**标记**（不拦截）：命中违规、低俗关键词的留言打上 `keyword_flagged` 标记进入后台"待复核"队列优先展示，由管理员处置（口径见 4.2、9.3；字段见 8.5）；

- **公开留言列表接口不得返回邮箱字段**（后端白名单序列化，见 2.3）；

- 上传文件安全校验：按 4.3 的类型白名单与大小上限执行；文件一律以随机键名存于对象存储，**不使用原始文件名参与路径构造**；对象存储桶设为私有读写；CDN 响应须带 `X-Content-Type-Options: nosniff` 且以附件形式下发，避免已上传文件被浏览器内联解析执行；

- 上传接口须校验登录态并具备 CSRF 防护。

### 5\.4 可拓展性需求

- 支持后续无限新增工具专题页面，无需改动网站整体架构；

- 支持后续新增功能（如工具点赞、收藏、用户星级评分）；

- 支持数据备份，可导出保存。**一期导出范围**：工具（含分类归属）、留言（含管理员回复）、分类清单三项；**导出格式**：CSV 与 JSON 各一份。**邮箱是否随导出输出由管理员在导出时勾选决定**（A-19 定稿）：默认**不含**，勾选"包含邮箱"后 CSV 与 JSON 均增加该字段，且**导出操作须留审计记录**（操作人 + 时间 + 是否含邮箱），便于事后追溯（见 2.3）。

### 8\.9 索引与删除策略

- 索引：`tools(slug)` 唯一索引；`tool_categories(name)` 唯一索引（见 8.2）；`release_notes(tool_id, version)` **联合唯一**（同工具同版本仅一条日志，见 8.3）；`messages(tool_id, created_at)` 复合索引（专题页留言分页）；`messages(audit_status, created_at)` 复合索引——公开留言列表恒以 `audit_status = 2` 过滤，该查询条件在两种审核策略下完全相同，**此索引一期即建**，避免二期切换时在线加索引（见 9.3）；`messages(is_pinned, created_at)` 索引（置顶优先排序）；`messages(status)`、`messages(category)` 索引（后台筛选）；`resource_files(tool_id, version)` 索引。
- **is_latest / latest_version 同步规则**：管理员将某条 `resource_files` 记录设为最新版时，须在同一事务内完成：① 同工具其余记录 `is_latest` 置 0；② 该记录置 1；③ `tools.latest_version` 更新为该记录 `version`。保证任一时刻同工具内至多一条 `is_latest = 1`。
- 删除策略：删除工具时，其 `release_notes`、`resource_files`、`messages`（及回复）级联删除；同时删除对象存储中的对应对象（含 `covers/` 前缀封面图），并对 CDN 做缓存刷新，不遗留任何仍可访问的残留副本。

## 九、上线前置与合规

本节为**上线阻塞项**，需在开发启动前确认，否则可能出现"开发完成但无法上线"的情况。

### 9\.1 备案与部署

- **部署方案（已确认，2026-09-21，A-11）**：**腾讯云轻量应用服务器（上海五区，4 核 4 GB / SSD 40 GB / 带宽 3 Mbps / 流量包 300 GB 月）** \+ 绑定独立域名；对象存储为**腾讯云 COS**（标准存储容量包 100 GB，大陆通用）。须完成 ICP 备案，归属**广西壮族自治区通信管理局**（备案按主体归属地受理，与服务器所在地无关）。含用户留言功能的站点在备案与内容监管上要求更严，需具备留言内容的日常管理与应急删除能力（本 PRD 的后台删除、待复核队列即为满足此项）；

- **上线节奏**：一期开发完成后**暂不公开上线**（个人项目，无时间压力）。备案与域名解析等上线前置手续可在正式公开前办理，**不阻塞开发启动**；

- 备选路径（若后续变更部署地）：中国香港（属中国境内，按现行制度无须 ICP 备案）或境外服务器可免备案，但访问速度与稳定性受影响，需另行评估——变更时须同步修订本节与《待确认参数台账》A-11；

- **带宽约束（3 Mbps，须纳入设计）**：服务器出网带宽约 375 KB/s，直接约束首屏加载（见 5.1）。因此**前端构建产物不得含大体积资源（图片一律走 COS），应用服务器只承载前端产物与 JSON API**——注意 v1.5 起后端**不输出任何 HTML 页面**，"只输出 HTML"的旧表述已作废；该项为 5.1 首屏指标的达标前提，非可选优化。注意本约束**不约束文件下载**——下载流量走 COS，不经应用服务器（见 4.3）；

- **COS 侧配额（官方，非瓶颈）**：中国大陆公有云地域**单账号单地域默认上下行各 15 Gbit/s**（=源站 3 Mbps 的 5000 倍）、每桶**读写各 30000 QPS**、**单文件下载热点频控 1000 QPS**。对本项目而言 COS 容量等同无上限，**真实瓶颈始终在源站带宽与用户侧宽带**。详见《前后端分离架构说明》§十一；

- 全站启用 HTTPS，域名与证书须在开发联调前就绪。

### 9\.2 隐私政策与免责声明

隐私政策页须覆盖：

| 项 | 内容 |
|---|---|
| 收集内容 | 昵称、留言内容；邮箱地址（**选填**） |
| 收集目的 | 收集产品使用反馈与缺陷报告；邮箱用于就本次留言进行问题跟进与处理结果告知 |
| 可见范围 | 昵称与留言内容公开可见；**邮箱仅站点管理员可见，不对任何访客公开** |
| 保存期限 | 随对应留言一并删除 |
| 删除方式 | 由管理员删除留言即同步删除；亦可来信要求删除 |

免责声明须覆盖：工具按现状提供、使用风险自负；文件由作者本人打包上传，下载后请自行核对校验值。

### 9\.3 留言内容责任与应急处理

- 一期审核策略（**已确认**）：**先发后审 \+ 关键词标记 \+ 定期清理**。留言提交后即时公开；命中关键词的留言**同样即时公开**，同时打上 `keyword_flagged` 标记（见 8.5）并在后台"待复核"队列优先展示，由管理员复核后决定保留或删除；违规内容可一键删除；

- **审核策略分期预留（2026-09-21 确认，终态为先审后发，A-14）**：一期按上述先发后审实现，但数据模型与接口为终态预留——`messages.audit_status` 字段一期即建、**不得省略**（新留言默认 2=已通过）；公开留言列表接口恒以 `audit_status = 2` 过滤（该查询条件在两种策略下完全相同，无需分支）；后台审核接口（单条审核 C-45、批量审核 C-46）一期实现但无待审数据，**C-47（一键通过全部）延至二期**（误操作风险高且一期无用，见附录C §6.2 Q-16）；站点配置 `message_audit_mode` 默认 `post`。**二期切换先审后发时仅需**：① `audit_status` 默认值 2 → 1；② 后台启用待审列表视图；③ 前台提交成功文案由"留言已发布"改为"留言已提交，审核通过后展示"；④ 切换 `message_audit_mode = pre`，无需改代码重新部署。**届时须同步修订**：本节、2.1.2、4.1、4.2、《待确认参数台账》A-5、《验收用例集》相关用例；

- 需具备后台一键删除任意留言（含其回复）的能力，用于应急处置；

- 删除留言时须同步删除该条记录的邮箱字段。
