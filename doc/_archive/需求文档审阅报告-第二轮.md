- **审阅日期**：2026-09-20
- **审阅对象**：`docs/doc/01-需求与范围/个人工具展示网站需求文档（PRD）.md` v1.2、`docs/doc/01-需求与范围/个人工具网站｜一期精简核心功能清单.md` v1.2

- **与第一轮报告的关系**：第一轮 P0/P1 问题经 ADR-001/002 与 v1.1/v1.2 修订后，**绝大多数已闭环**（见第二节）。本报告只记录**当前版本仍然存在**的问题。

## 一、总体结论

**结论：文档尚不具备直接进入接口设计的条件，需再补一轮修订；但修订内容不触及已定架构，可快速闭环。**

判定依据：文档在**需求层**（功能范围、边界、合规、字段语义）已完成绝大部分工作，质量显著高于第一轮；缺口集中在**交付层**——具体表现为"接口层零定义""关键参量未定值""一期范围三处口径未闭合""验收用例未覆盖一期范围"四类。

| 评估维度 | 就绪度 | 判定 |
|---|---|---|
| 需求范围与边界（做什么／不做什么） | 高 | ADR-001 的 In/Out Scope 与边界判例可直接作为开发挡板 |
| 数据模型与字段语义 | 中高（约 85%） | 7 实体已成型，缺 3 处（站点配置表、封面图规则、关键词复核标记） |
| 接口定义与统一约定 | **未就绪** | 全文仅出现 2 个接口名，无路径、方法、入参、出参、鉴权、分页、错误码 |
| 参数完备性 | 中（约 70%） | 限流阈值、登录锁定阈值、内容长度上限、分页大小、上传签名有效期等未定值 |
| 验收标准 | 中（约 60%） | 19 条用例未覆盖一期范围中的 12 项功能，交付标准无法据此判定"通过" |
| 上线合规前置 | 已识别、未决策 | 服务器归属地（是否 ICP 备案）仍未定，属唯一的上线级阻塞项 |

**不建议"边开发边补"的项目**：限流阈值、登录锁定阈值、审核策略落地口径与数据模型缺口——这四项一旦按错误假设进入实现，改动会扩散到接口契约与数据表，返工成本最高。

## 二、已达标项（不再提出问题的部分）

为避免重复讨论，以下项经逐条核对**确认已闭环**，后续修订不必再动：

1. **范围收敛**：ADR-001 将"托管"限定为文件存储与下载，8 类排除项 + 5 条边界判例（Web 工具、Python 脚本、加密包、zip 目录、APK 二维码）；PRD 1.2、2.1.2、4.3 与清单四已同步。
2. **留言反馈管道**：选填邮箱字段、三处标准文案一致性要求、BUG 结构化三字段（`os_platform` / `tool_version` / `repro_steps`）、回复无通知的已知限制声明与二期归属，均已落地。
3. **两文档主要口径对齐**（逐项验证通过）：留言分类 4 类、留言状态 4 种、文件类型白名单（允许 16 项／拒绝 10 项，两份文档逐字一致）、单文件上限 200 MB、下载路径 `/download/{file_id}` + 302 签名跳转、不设独立"全部工具列表页"、"关于我"页入一期、一期不发任何邮件。
4. **存储与分发方案**：对象存储私有桶 + CDN 直链 + 防盗链 + 签名时效，且成本告警要求已写入。
5. **合规章节**：备案归属、HTTPS、隐私政策五要素表、免责声明、内容责任与应急删除、后台安全，均已建档。

## 三、P0 阻塞项（不解决则不应开始接口设计）

### P0-1　一期范围在三个位置口径不一致，范围未闭合

**位置**：PRD §6.1（一期必做）↔ PRD §2.2（后台功能详述）↔ 清单 §三

**问题**：§6.1 是唯一声明"一期上线"的清单，但 §2.2 详述的功能有 7 项未被 §6.1 收录，其中 4 项同时**被清单收录**，形成"PRD 详述有、PRD 范围表无、清单有"的三方错位：

| 功能 | PRD 详述 | PRD §6.1 一期必做 | 清单 |
|---|---|---|---|
| 工具分类管理（新增/编辑/删除） | §2.2.1 有 | **未列** | **未列** |
| 存储占用查看 | §2.2.1 有 | **未列** | **未列** |
| 留言置顶 | §2.2.2 有（且 §4.1 前台排序、§8.5 `is_pinned` 均依赖它） | **未列** | **未列** |
| 反馈统计（数量计数） | §2.2.2 有 | **未列** | 清单四称"不做复杂统计"，口径不明 |
| 网站基础设置（简介/标题/版权/密码/留言开关） | §2.2.3 有 | **未列** | **§三.3 有** |
| 外链型资源维护（`repo_url` / `web_url`） | §8.1 有字段、§2.1.2 有描述 | **未列** | **§三.1 有** |
| 数据导出／备份 | §5.4 有 | **未列** | **未列** |

**为什么阻塞**：开发按 §2.2 实现则范围超出一期，按 §6.1 实现则"留言置顶"缺失（前台排序规则 §4.1 将无法实现）。二者都会在联调阶段暴露。

**另有一处直接矛盾**：§2.2.1 写"支持新增、编辑、删除分类"，而附录 A 的 A-6 已按建议值执行"一期固定 4 类"，清单 §二.1 亦写死 4 类。**正文与已接受的参数值冲突**，开发无法判断后台是否要做分类 CRUD 接口。

**需补充**：① 以 §6.1 为权威范围表，逐条与 §2.x 做双向对齐（建议增加"详述位置"列）；② 将 §2.2.1 分类管理改写为"分类为固定 4 类，后台不可增删，仅可调整排序（`sort_order`）"或明确否决 A-6；③ 明确反馈统计一期是否只做计数。

### P0-2　接口层零定义，无法开展接口设计

**位置**：全文。目前仅出现两处接口名——§4.3 的 `/download/{file_id}` 与 §2.3 的"公开留言列表接口"。

**问题**：用户本次诉求的"接口设计"，需要的输入是：路由规范、请求/响应结构、鉴权方式、分页约定、错误码。当前文档全部缺失。具体缺口：

1. **无接口清单**。前台至少需要：首页工具列表（含分类筛选、关键词搜索）、专题页详情（含更新日志、文件列表）、留言分页列表、留言提交、下载重定向。后台至少需要：登录/登出、工具 CRUD、上下架、版本与文件管理（预签名签发 + 完成登记）、留言列表/详情/回复/状态/置顶/删除、站点设置读写。均未列出。
2. **无路由规范**。专题页 URL 形态未定（仅定了 `slug`），后台入口路径未定（§9.4 只说"与前台分离、不在前台暴露"）。
3. **无鉴权约定**。后台登录用 session 还是 JWT？有效期？CSRF 用 token 头还是 cookie 双提交？§5.3 仅要求"具备 CSRF 防护"。
4. **无分页约定**。§2.1.2"支持留言分页展示"未给默认每页条数与上限。
5. **无错误响应结构**。B-9 要求"后端拒绝"、B-14 要求"提示明确"，但未定义统一错误体（code/message）与 HTTP 状态码。

**需补充**：在 PRD 新增附录 C《接口清单与统一约定》，内容为：路由命名与版本前缀、鉴权方案、分页参数（建议 `page` / `page_size`，默认 20、上限 100）、统一响应与错误码表、时间与字符集约定、各接口的入参出参字段表。

### P0-4　数据模型 4 处缺口

**位置**：PRD §8

1. **缺站点配置实体**。§2.2.3 的网站标题、首页简介、版权信息、留言开关（以及 P0-3 第 6 项的轮询间隔）需要持久化，但 §8 声称的 7 个实体中无对应表。**这 5 项功能当前没有数据落点。**
2. **封面图无规则、与存储方案不自洽**。§2.2.1 要求"上传封面图"、§8.1 有 `cover_path`，但：§4.3 的类型白名单（16 项）**不含任何图片格式**；封面图无大小与尺寸限制；`cover_path` 的命名与 §8.4 的 `object_key` 约定不一致；封面图是**公开展示**的图片，而对象存储桶为**私有读写**——公开访问路径未定义（走 CDN 公开目录？走签名 URL？）。
3. **审核策略缺少承载字段**。§9.3 规定"命中关键词的进入待复核队列"，但 §8.5 无"是否命中关键词／待复核"标记字段，`status` 的四个值（未处理/已处理/已跟进/无需处理）也不含该项。**该队列当前无法实现。**
4. **两处一致性规则未定**：`tools.latest_version`（冗余字段）与 `resource_files.is_latest`（同工具内唯一）的同步与时序规则；`tools.platforms` 多选的存储形式（逗号分隔字符串还是关联表）——后者直接决定接口返回是数组还是字符串。

**需补充**：新增 `site_settings` 实体；补封面图类型（建议 `.jpg .jpeg .png .webp`）、大小上限（建议 2 MB）、宽高比与公开访问方式；新增 `keyword_flagged` 类标记字段；明确上述两条一致性规则。

### P0-5　审核策略的落地口径自相矛盾

**位置**：§9.3 内部、与 §4.2 交叉

**原文**："留言提交后即时公开；命中关键词的进入待复核队列，由管理员定期清理。"

**问题**：前半句是"先发后审"（命中关键词的内容也已公开），后半句"进入待复核队列"通常理解为"暂不公开、等待复核"（即先审后发）。两种解释对应完全不同的实现：前者需要"已公开 + 标记待清理"，后者需要"待审核状态 + 前台不可见"。**开发无法从文本判断命中关键词的留言是否对访客可见**，而这会同时影响提交接口的返回、列表接口的过滤条件与状态字段设计。

**需补充**：明确写为下列之一并同步 §4.2、§8.5：
- **A（推荐，与已确认的"先发后审"一致）**：命中关键词的留言**照常公开**，仅打上"待复核"标记进入后台队列，由管理员定期清理；
- **B**：命中关键词的留言**不公开**，状态为"待审核"，需管理员放行。

### P0-6　验收用例未覆盖一期范围，交付标准不可判定

**位置**：附录 B（19 条）与 §七 交付标准

**问题**：§七 写"通过附录 B 全部验收用例"，但用例未覆盖一期范围内的以下功能：工具分类管理、留言置顶、留言状态标记、按工具/分类/状态筛选（仅覆盖了邮箱筛选 B-18）、数据导出与备份、后台登录失败锁定、关键词拦截与复核队列、封面图上传、站点设置生效、搜索与分类筛选叠加、上下架与下载链接失效的联动。**用例覆盖率不足，等于验收依据不足。**

**需补充**：按 P0-1 对齐后的一期范围，逐条补齐用例（建议补 10–12 条）。同时将 §5.1 的"打开延迟 ≤ 1.5s""支持多用户同时访问，无卡顿"改写为可测量条件——当前表述无网络环境、设备、首屏定义与并发量级，仍属不可验收（建议改为"4G／家庭宽带下首屏 P75 ≤ 1.5 s""50 并发下请求错误率 < 1%"）。

## 五、P2 编辑级问题

1. **表述需按中国主权规范修正**：§9.1 与清单 A.2 第 13 项均写作"境外或**中国香港**服务器"，将中国香港与境外并列。建议改为三方表述——"中国境内（大陆）服务器（需 ICP 备案）／中国香港服务器（属中国境内，按现行备案制度无需 ICP 备案）／其他境外服务器"。
2. **附录 A 编号不可追溯**：A-1…A-10 编号断档，且与第一轮报告的决策表编号不对应（此处 A-1 为"单文件大小上限"，而第一轮报告第 1 项为"'托管'的准确含义"）。建议改为连续编号，或增加"来源"列指向第一轮报告条目。
3. **ADR-001 §3.2 计数笔误**："前四类…后五类…"，实际拒绝列表为 4 + 6 = 10 项，"后五类"应为"后六类"。
4. **截图字段位**：清单四称"一期保留字段位不实现"，但 §8.5 无对应字段。二者取一——要么现在建字段（避免二期改表），要么删除该表述。
5. **分享元数据未纳入**：§4.1 以"可单独分享、收藏"为卖点，但未要求 OG 标题/描述/缩略图（第一轮 P1-8 未闭环）。个人站可标注为"不予实现"以消除歧义。
6. **索引建议**：§8.8 建议补 `messages(is_pinned, created_at)`（专题页"置顶优先 + 时间倒序"排序）与 `resource_files(is_latest)`。
7. **唯一性约束**：§2.1.2 称"一条日志对应一个版本号"，但 §8.3 未对 `(tool_id, version)` 建唯一约束。
8. **未定义项**：浏览器兼容范围（建议"近两年 Chrome/Edge/Safari/微信内置浏览器"）、留言时间的展示格式与时区。

## 六、必须由你决策的两项（其余均为可由开发者按建议值执行的补充）

| # | 决策项 | 为什么必须由你定 | 备选 |
|---|---|---|---|
| 1 | **服务器归属地**（大陆 / 中国香港 / 境外） | 唯一的上线级阻塞项：大陆需 ICP 备案（周期以周计，建议**立即启动**）；同时决定对象存储与 CDN 的实名与备案要求。注意此项在清单 A.2 中列为"待确认"，但 PRD 附录 A 未收录，**两处需同步** | 大陆（合规与速度最优，需备案）／中国香港（免备案，速度尚可）／境外（免备案，延迟高） |

## 七、建议的下一步（一轮即可闭环）

1. **文档结构建议**：清单当前与 PRD 存在大段平行描述，这已是本轮 3 处口径分歧的来源（分类管理、置顶、反馈统计）。建议将清单**降格为"范围索引表"**——只保留"能力条目 + 是否一期 + PRD 详述位置"三列，删除重复的规则正文，使 PRD 成为唯一事实源，从结构上消除未来漂移。
2. **本轮修订产出物（3 份）**：① PRD 附录 C《接口清单与统一约定》（解除 P0-2）；②《一期范围对齐表》（§6.1 ↔ §2.x ↔ 清单三向闭合，解除 P0-1）；③ 数据模型增补（`site_settings`、封面图规则、关键词标记字段、两条一致性规则，解除 P0-4）。
3. **可并行推进、不被本轮修订阻塞的工作**：ICP 备案（周期最长，建议今日启动）、对象存储与 CDN 开通及防盗链配置、前端页面骨架与视觉风格、页面路由表。
4. **修订完成后的判定**：P0 六项闭环 + 两项决策落定即可**直接进入接口设计与实现**，无需再增加一轮完整评审；建议只做一次"接口清单评审"（30 分钟级）确认契约。
