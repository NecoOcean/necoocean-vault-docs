# necoocean-vault-docs

> NecoOcean 个人工具展示网站的**文档仓库**——需求、设计、规范与决策的唯一事实源。

本仓库是「三仓库 + 本地工作区」形态中的**文档仓库**：它不承载任何可部署产物，只承载**契约与决策**。后端与前端各自是独立仓库，代码内禁止出现第二份接口定义。

**仓库根 = `docs/` 目录本身**（远端 `necoocean-vault-docs`，`main` 分支）。**同一仓库有两个名字**：远端叫 `necoocean-vault-docs`，本地工作区中的目录名叫 `docs`。克隆到别处时只有远端名存在，故克隆目录里不再有 `docs/` 这一层——文档路径直接是 `doc/…`、`design/…`、`文档规范/…`。

## 技术栈

前端 `Vue 3 + Vite` · 后端 `Java 17 + Spring Boot 3.x`（仅 JSON API） · 数据库 `MySQL 8` · 存储 `腾讯云 COS`

部署：单台腾讯云轻量应用服务器（上海五区，4C4G / 3 Mbps），`Nginx + systemd`，同源部署不启用 CORS。

## 目录结构

```
docs/                            # ← 本仓库根
├── README.md                    # 本文
├── CHANGELOG.md                 # 跨文档变更记录 + 三仓库版本对应表（N-3，已建成）
├── doc/                         # 需求、设计、进度类文档（按生命周期分四类）
│   ├── 01-需求与范围/           # PRD、一期清单、ADR
│   ├── 02-设计与实现/           # 系统设计、架构、接口、选型、参数台账、验收用例
│   ├── 03-进度与交付/           # 进度分析、部署运维手册；测试用例集仍待建
│   └── _archive/                # 快照类文档，不随项目更新，仅作追溯
├── design/                      # UI 设计交付物（规范 + 原型）
└── 文档规范/                    # 撰写、图表、工程约定规范
```

**引用口径（重要）**：仓库内文档互相引用时，路径**一律写成** `docs/doc/<分类>/x.md`、`docs/design/x.md`、`docs/文档规范/x.md`。

这样定的理由不是"文件管理器里能点开"，而是**全文检索时唯一定位**——`docs/doc/…` 这串文本在整个文档库中含义恒定，搜"哪些文档引用了 X"才能一次命中。代价是：**在克隆目录中阅读时，须自行去掉开头 `docs/` 前缀**（因该层由本地目录名提供，克隆后不存在）。规范依据见 `文档规范/仓库形态规范.md` §3.1.1。

**同级目录**（不属本仓库，已由 `.gitignore` 排除）：

```
D:\Data\code\necoocean-vault\    # 本地工作区，不是 git 根
├── docs\                        # ← 本仓库根（远端 necoocean-vault-docs）
├── necoocean-tools-backend\     # 后端仓库，独立 .git
└── necoocean-tools-frontend\    # 前端仓库，尚未建立
```

> `.gitignore` 位于仓库根，两个兄弟仓库在**上一级**，故其中以 `../necoocean-tools-backend/` 这类前缀排除——这是「仓库根 = `docs/`、而兄弟仓库在 `docs/` 之外」这一结构的必然结果。

## 核心约束（不可违背）

1. **3 Mbps 带宽是本项目最紧约束**——首屏 gzip 后 ≤163 KB；达标场景为并发峰值 ≤3 人；图片与下载文件一律走 COS，不经源站。
2. **后端禁止输出任何 HTML 页面**——jar 内不得含 `.html`；除 `/download/{file_id}` 的 302 外，所有响应 `Content-Type` 必为 JSON。
3. **接口契约唯一事实源在本仓库**——代码仓库内禁止第二份定义；变更顺序不可逆：先改契约 → 后端实现 → 前端跟进。
4. **公开接口不得返回 `contact_email`**——必须用独立白名单序列化器，而非在通用序列化器上加 `exclude`（两者"新增字段时的失败方向"相反）。
5. **不引入任何 Web 框架/UI 组件库/webfont**——前端全部 CSS 变量 + 原生 API。中文 webfont 子集数百 KB，会直接击穿首屏预算。
6. **日志骨架先于任何业务功能**——所有新项目或接手的代码库，第一件事是审查日志能力。
7. **COS 建桶地域必须与服务器同在上海**——跨地域会产生流量费与回源延迟。
8. **反代后必须正确取 `X-Forwarded-For` 首段**——否则限流会误伤全部访客；取不到时降级为不限流，不得归入同一桶。

## 文档撰写规矩（三条）

本仓库的文档可读性不来自文采，来自纪律。完整规范见 `文档规范/`，以下三条最常被违反：

1. **文档头部必须显式声明"还有无未决项，共几项"**——把"能不能开工"从"通读全文后判断"降为"打开文档 5 秒内可见"。
2. **引用路径规则**（`文档规范/README.md` §4.1.2）：同目录用裸文件名；跨目录用**仓库根相对完整路径** `docs/doc/<分类>/x.md`。跨目录必须写全的唯一理由——搜索"哪些文档引用了 X"时只有完整路径能一次命中。
3. **`_archive/` 内文档不作事实源**——其结论若被采纳，须回填至 01/02/03 中的相应文档。

## 快速开始

本仓库无构建步骤。阅读路径建议：

```bash
git clone https://github.com/NecoOcean/necoocean-vault-docs.git
cd necoocean-vault-docs
```

1. 读本文「文档导航」，定位到需要的文档；
2. 打开 `design/prototype/index.html` 可离线查看首页高保真原型；
3. 新建任何文档前，先读 `文档规范/README.md`。

部署操作见 `docs/doc/03-进度与交付/部署运维手册.md`。
